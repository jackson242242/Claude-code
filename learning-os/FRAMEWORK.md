# Learning OS — 学习产品框架

> 一套撑起**所有课程**的脊梁:价值体系 + 架构 + 进阶模型 + 长期计划。
> 让理财、AI、艺术、设计……不是 8 门散课,而是 **一个有信念、有结构、能从入门走到精通的学习产品**。
>
> 这份框架不是凭空设计的——它是把已经验证有效的 **「Thomas's Money Adventure」**(PR #41,
> `kids-investing-course/`)里那套教学 DNA 抽象出来,变成可复用的母版。任何新课程都按这套来建。
>
> **配套文档:**
> - [`ENGAGEMENT.md`](./ENGAGEMENT.md) — 留存引擎(心理学钩子、通知/邮件、小组榜、badge、伦理护栏)
> - [`ARCHITECTURE.md`](./ARCHITECTURE.md) — 可行性 / 稳定性 / 可扩展(内容即数据)/ 排名系统 / 技术栈
> - [`MONETIZATION.md`](./MONETIZATION.md) — 盈利模式(订阅 vs 广告,推荐 freemium + 家庭版)

---

## 0. 一句话定位

**每一门课都是同一根脊梁上的一节;学习者在脊梁上从入门一步步爬到精通,跨领域之间互相咬合。**

- 学习者画像是**参数**,不是限制:同一套架构既能服务"9 岁学股票的 Thomas",也能服务"成年人学 LLM"。
- 每门课都申明 **Who it's for / Goal**(沿用 Thomas 课的开篇格式),其余结构全部统一。

### ⭐ 主次原则:重点是学习,mascot 是钩子

> **mascot / streak / badge / 排行榜 = 把人吸引进来、拉回来的"诱饵";真正的"主菜"是学习内容的深度。**
>
> - 钩子负责"让人来、让人留";内容负责"让人真的学到、学深"。两者都要,但**永远不能让游戏机制
>   稀释学习质量**——绝不为了多发奖励而注水关卡、降低门槛、用花哨动画掩盖空洞内容。
> - 检验标准:**拿掉所有 mascot 和奖励,这门课本身还值得学吗?** 必须是"值得"。
> - 因此 `ENGAGEMENT.md`(钩子)服务于 `FRAMEWORK.md`(学习),不是反过来。
> - 配套:学习深度本身有专门的设计(往深挖、L0→L4 阶梯、讲回来验证真懂),见 §1 价值体系 与 §3 进阶模型。

## 1. 价值体系(信念)

> 这是产品的"宪法"。每一条都来自 Money Adventure 里被验证过的做法,不是空话。

| # | 信念 | 它在课里长什么样(证据) |
|---|------|------------------------|
| 1 | **理解 > 记忆** | "讲回来才算学会"——每关结束让学习者用一句话复述。If he can teach it, he's learned it. |
| 2 | **真类比通向真概念** | 用 pizza=公司 入门,但**真的**教 P/E、leverage、carry——类比是桥,不是终点。 |
| 3 | **做中学,允许犯错** | 互动 mission + 线下活动;"losing pretend money is the cheapest lesson he'll ever get." |
| 4 | **进阶有门禁** | 过完 Chapter 1 的测验才解锁 Chapter 2。**先掌握,再前进**(mastery before advancement)。 |
| 5 | **短而频 > 长而闷** | 15–25 分钟一关,每周 ~2 关。"Stop while it's still fun." 间隔重复打败填鸭。 |
| 6 | **成长看得见** | ⭐ / 奖杯 / 等级 / 地图。13 颗星集齐 → Money Master。进度是动力。 |
| 7 | **长期复利** | 课程的元主题——"早开始 + 持续 = 滚雪球"——对**学习本身**同样成立。这是整个产品的世界观。 |

## 2. 架构(五层嵌套)

任何内容都落在这五层里。建新课 = 往这五层里填东西,不发明新结构。

```
Learning OS                ← 整个产品:跨所有领域的地图 + 长期计划
 └─ School 学院             ← 一个领域簇(Money & Markets / AI & Machines / Art & Design)
     └─ Track 课程          ← 一段领域旅程(= 现在的一门"课",如 Money Adventure)
         └─ Chapter 章      ← 一个主题关卡簇(如 "The Basics" / "The Money World")
             └─ Mission 关  ← 原子:15–25 分钟,一个概念,互动 + 讲回来
```

### Mission 的标准解剖(母版)

> 每一关都长这样,不管是 9 岁学股票还是成年人学反向传播。**统一了它,任何 agent 都能按模板量产关卡。**

1. **一个核心概念**(Key idea,一句话)——一关只讲一件事。
2. **一个真类比入口**——降低恐惧感的具象比喻。
3. **一个可玩的互动**——滑块 / 小游戏 / 模拟,让概念"动起来"。
4. **一个线下活动**——把概念带进真实生活,这是"记住"的地方。
5. **一个讲回来的问题**(Ask him/her)——检验是否真懂。
6. **一颗 ⭐**——可见的完成反馈。

### 实现形态(沿用已验证的)

- **自包含 `index.html`**:纯静态、离线可用、浏览器/平板直接开(Money Adventure 已证明可行)。
- **`COURSE_PLAN.md`**:家长/学习者引导手册,人类可读。
- 一个 Track = 一个目录(如 `kids-investing-course/`),内含上述两件。

## 3. 进阶模型(从入门到精通)

### 五个等级(每个 Track 内部 + 跨 Track 通用)

| 等级 | 名称 | 学习者能做什么 | 门禁(怎么升级) |
|------|------|----------------|------------------|
| **L0** | 入门 Spark | 知道这个领域在讲什么、为什么有趣 | 完成"为什么"那一关 |
| **L1** | 基础 Basics | 掌握核心概念、能用一句话解释 | 通过基础测验(如 The Big Money Quiz) |
| **L2** | 进阶 Builder | 把概念组合起来解决问题 | 完成一个综合 mission(如 Lemonade Stock Market) |
| **L3** | 实战 Operator | 在仿真/真实情境里做决策 | 完成一个项目(如 family-office plan) |
| **L4** | 精通 Master | 能教别人、能迁移到新情境 | 能把它讲给一个新手听懂 |

**规则:门禁不可跳。** 没过 L1 测验,L2 章不解锁——这正是 Money Adventure 里"过基础测验才解锁 Money World"的推广。

## 4. 领域地图(三所学院 + 进阶阶梯)

把你列的领域,按**天然的依赖关系**排成阶梯。箭头 = "建议先学左边"。

### 🏦 School of Money & Markets(已开张)
```
个人理财基础  →  市场与投资  →  私募股权 PE
(Personal      (Stocks,        (LBO, fund,
 finance)       diversification) LP/GP, carry)
```
> **现状:** Money Adventure 已覆盖 个人理财基础 + 市场,并把 PE 做成了 kid 版(Mission 9–10)。
> 这是整个产品里**最成熟的一条 Track**,可作其他领域的参照标准。

### 🤖 School of AI & Machines
```
机器学习 ML  →  深度学习 DL  →  大语言模型 LLM  →  AI Agent
(什么是模型、    (神经网络、       (transformer、     (工具调用、
 训练、过拟合)    反向传播)         tokens、注意力)    规划、记忆)
```
> 严格的技术阶梯:不懂 ML 的"训练/损失"概念,DL 的反向传播讲不通;不懂 DL,LLM 是黑箱;
> 不懂 LLM,Agent 只是魔法。**必须按序。**

### 🎨 School of Art & Design
```
艺术基础/审美  →  设计原理        →  应用设计
(看懂、构图、    (对比/层级/留白/   (UI、品牌、
 色彩、风格)      网格、字体)        信息设计)
```
> 艺术训练"眼睛"(审美判断),设计把审美变成"解决问题的规则"。先有眼,后有手。

### 跨学院的咬合
- **PE**(Money)其实依赖一点点 **私募基金数学** → 可与 L2 数学素养互通。
- **AI Agent**(Machines)的产品形态,需要 **设计**(Art)来做交互——两所学院在 L3 实战处汇合。
- 每个领域的 **L4 精通** 都用同一把尺子:**能教会一个新手。**

## 5. 长期学习计划(分阶段路线图)

> 不追求"同时开八门",而是按依赖关系**分阶段铺开**,每阶段都先把上一阶段的 Track 推到至少 L1。
> 这本身就是信念 #7(复利):稳定地一节一节加,而不是一次塞满。

| 阶段 | 目标 | 新增 Track | 产出 |
|------|------|-----------|------|
| **Phase 0(已完成)** | 验证 DNA | Money Adventure(理财+PE,kid 版) | PR #41,13 missions ✅ |
| **Phase 1** | 把框架固化 + 复用 | (无新课)抽出本框架 + Track 模板 | 本文档 + `_template/` 脚手架 |
| **Phase 2** | 开第二所学院 | ML 基础 → 深度学习 | AI & Machines 学院启动 |
| **Phase 3** | 技术阶梯爬到顶 | LLM → AI Agent | 一条完整的 AI Track |
| **Phase 4** | 开第三所学院 | 艺术审美 → 设计原理 | Art & Design 学院启动 |
| **Phase 5** | 跨领域实战 | "用 AI Agent + 设计 做一个产品" | L3/L4 综合项目,三学院汇合 |

> 顺序不是死的:你可以把 Phase 4(艺术/设计)提前。但**技术阶梯(ML→DL→LLM→Agent)内部不能乱序。**

## 7. Mascot 系统(一整个动物园,养成 + 收集)

> 灵感:Duolingo 有一只鸟(Duo)。我们不是养一只——是**养一整个动物园 🦤🐼🦒🦅**。
> **每个领域一只不同的动物**,各自随学习**长大**(Tamagotchi:每天喂养,坚持几年长成成年)。
> 学的领域越多,动物园越大——这本身就是强力的**收集 / 集齐(completionism)动力**。

### 当前指派(占位,可随时换/新增)

| 学院 / 领域 | Mascot | 寓意 |
|------|--------|------|
| 🏦 Money & Markets | **Emu 鸸鹋** | 跑得快、存得住、脚踏实地——理财的耐心与冲刺。 |
| 🎨 Art & Design | **Panda 熊猫** | 黑白构图、慢工出细活——审美与设计的从容。 |
| 🤖 AI & Machines | **Giraffe 长颈鹿** | 站得高看得远、一层层往上够——技术阶梯。 |
| 🦅 (待定领域) | **Eagle 鹰** | 锐眼、果断、抓住时机——可给"交易/决策"类。 |

> 一个领域一只。新领域开张就分配一只新动物。**鹰、猫头鹰、狐狸、海豚……动物池可以一直扩。**

### 收集机制(My Zoo)

- **主屏是"我的动物园"**:已养的动物都在,点进去喂/看成长;未解锁的领域显示"蛋的剪影",勾人去解锁。
- **每只独立成长**:你的 Emu 可能成年了,Giraffe 还是蛋——一眼看出你在哪个领域走多远。
- **集齐 = 终极成就**:养大一只是 mastery,养满整个动物园是这个产品的"通关"。
- **可命名 / 装扮**:每只都是"用户自己的",强化投入感(见 `ENGAGEMENT.md` 的 Investment 环节)。

### 成长阶段(直接复用 L0–L4 等级)

mascot 的体型 = 学习者在该学院的累计掌握度。**等级即形态,无需另造一套数值。**

| 等级 | mascot 形态 | 含义 |
|------|------------|------|
| L0 入门 | 🥚 **蛋 Egg** | 刚开始,还没破壳 |
| L1 基础 | 🐣 **幼崽 Hatchling** | 会走路了,掌握核心概念 |
| L2 进阶 | **少年 Juvenile** | 能组合概念解决问题 |
| L3 实战 | **青年 Sub-adult** | 在仿真/真实情境里独立决策 |
| L4 精通 | **成年 Adult** 🦤🐼🦒 | 长大成年 = 能教别人 = 学习者 ready |

### 养成机制(Tamagotchi)

- **每天学一点 = 喂养。** 一节 mission(或一次复习)= 一次喂食 → 累计 XP + 维持 streak。
- **XP 推动等级,等级推动形态。** 攒够 XP 解锁下一等级 → mascot 长大一个阶段(有破壳/换毛的过场动画)。
- **跨年坚持 → 成年。** 走完一所学院的全部 Track,mascot 成年。"学几年,动物长成大人"正是这条。
- **正向为主,不用愧疚机制。** 断 streak 不"惩罚"——mascot 只是"等你回来",不卖惨、不施压
  (信念 #5:short and frequent,让人想回来,而不是怕)。

## 8. 形态:Duolingo 式(动画,不只是文字)

- **不是读文档,是玩关卡。** 每个 mission 是一屏可点的互动(滑块/小游戏/拖拽),配**简单动画**。
- **动画用 SVG + CSS / Lottie**,不是视频:矢量、清晰、体积小,而且**可编程**——
  mascot 从蛋到成年的"长大"可以用同一套 SVG 骨架按参数缩放/变形,而不是为每个阶段画一张图。
- **每屏一个核心动作 + 即时反馈**(对 → mascot 开心跳一下;错 → 温和提示再试)。
- 仍然保留线下活动和"讲回来"——动画负责吸引,讲回来负责真懂。

## 9. 工程:在哪做 / repo / 素材

### 平台:Touchscreen-only(触屏专用),不做 desktop

**核心约束:这是一个纯触屏产品。** 不只是 iPad——是任何触屏设备(手机 + 平板,iOS + Android)。

- **纯触摸交互:** 手势驱动(点/拖/滑/捏),**没有鼠标 hover、没有键盘依赖**。
- **尽量不打字:** 用点选/滑块/拖拽代替输入框——对孩子和触屏都更友好(注册/命名等少数处才用软键盘)。
- **大热区、拇指可达:** 主操作放屏幕下方拇指区;按钮够大,适合小手和移动场景。
- **响应式:** 手机竖屏(单列)+ 平板(更大画布,My Zoo 和 mascot 更突出)。
- **离线友好:** 关卡能离线玩,联网只用于同步进度/榜单/邮件。

### 交付壳:Expo / React Native(已定)✅

一套代码同时出 **iOS + Android** 原生 app,通知能力最好,能上 App Store / Play Store——
和"touchscreen-only(含 Android 触屏)"完全契合。

**工具链现实(诚实说清,免得踩坑):**

| 环节 | 能不能在本远程环境做 | 需要什么 |
|------|---------------------|---------|
| 搭工程 + 写全部 app 代码 | ✅ 能(node22 + npm + 能连 registry) | 无 |
| **真机预览/调试** | ✅ 你手机装 **Expo Go**,扫码即跑,改代码秒刷 | 一台触屏手机/平板 + Expo Go(免费) |
| 出**正式安装包 / 上架 / 生产推送** | ⚠️ 用 **EAS Build**(Expo 云构建,无需 Mac) | Expo 账号(免费档)+ **苹果开发者 $99/年**;Android **Google Play $25 一次性** |

> 关键:**开发阶段不需要 Mac**——我在这里写码,你用 Expo Go 在真触屏设备上看效果。
> 只有"上架 + 正式推送证书"才需要那两个开发者账号。这笔钱是 App Store 的门票,不是我们能绕过的。

### 能不能 remote(在 Claude Code on the web)做?

**能。** 这个产品是静态前端(`index.html` + SVG/Lottie + 一点 JS 存进度),最适合在这种环境里建。
唯一要记住的:**这个容器是临时的,任何东西必须 commit + push 才留得住**(我已经在这么做)。
部署是另一回事——仓库已经有 `render.yaml`,可以挂到 Render 之类的平台上线。

### repo 放哪?

| 方案 | 适合 | 取舍 |
|------|------|------|
| **现在:** 留在本 portfolio repo 的 `learning-os/`(就是当前位置) | 快速原型、验证框架 | 和 World Cup app 等混在一起,但起步最快 |
| **将来:** 独立成自己的 repo + 自己的 CI/部署 | 它长成真正的产品后 | 干净、可单独上线,但要建新仓库 |

**建议:先在 `learning-os/` 里把第一门 Duolingo 式 Track 原型跑通,有样子了再"毕业"到独立 repo。**
要独立 repo 时我可以帮你建(GitHub 工具重连后即可)。

### 素材(mascot + 动画)从哪来?

按"自给自足 → 越省外部依赖越好"排序:

1. **SVG 骨架自己搭(主力)。** mascot 的成长形态、关卡里的小动画,用代码画的 SVG/Lottie——
   可编程、可按等级变形、零版权问题。Tamagotchi 式"长大"必须用这种可控方式,AI 生成图
   很难保证"同一只动物不同阶段长得一致"。
2. **AI 生成参考稿(辅助)。** 仓库里已经有 `design-asset` skill(走 OpenAI Images 生成图并接进 app)——
   可以先用它生成每只 mascot 的设计参考稿/定妆照,再据此搭 SVG 骨架。
3. **开源图标/Lottie 库** 补充通用元素(硬币、图表、星星),挑 MIT/CC0 许可的即可。

> 诚实提醒:第 2 步"用 AI 生成一整套从蛋到成年、风格一致的动物"目前很难一次到位,
> 通常要"AI 出定妆照 → 人/代码搭可变形骨架"两步走。我不会假装一键就能拿到全套素材。
