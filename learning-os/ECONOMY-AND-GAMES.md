# 金币经济 + 游戏厅 — Economy & Games

> 在「学课程」之外，给产品加一条**并行的金融游戏线**：用**虚拟金币（Coins）**把学习和小游戏
> 串成一个经济系统——**学课程赚金币、玩游戏赚金币**，每周比**谁赚得最多**，动态里看**谁学了几天、学了什么**，
> 称号与徽章以**财富**为标尺。
>
> 配套：[`FRAMEWORK.md`](./FRAMEWORK.md)（脊梁）· [`ENGAGEMENT.md`](./ENGAGEMENT.md)（留存引擎，本文复用它的联赛/徽章/伦理护栏）。
>
> ⚠️ **两条铁律，贯穿全文：**
> 1. **金币 = 游戏内虚拟货币，永远不是真钱**（不可充值、不可提现）。这是金融 app，"分数"本身就是"钱"——
>    主题天然贴合，且**零赌博 / 零支付牌照 / 零监管风险**。
> 2. **用户含 9 岁的 Thomas。** 全程按 **bright patterns（亮模式）**——所有"赢钱"机制必须是**技能/知识驱动，不是运气驱动**
>    （见 §7 防赌博防火墙）。

## 0. 一句话

**金币是把"学习"和"游戏"焊在一起的经济血液。** 你因为**学懂了**而能在游戏里赢更多金币，
金币推动财富榜、称号、装扮——但**主菜永远是学习内容的深度**（`FRAMEWORK.md` §0 主次原则）。
**学得越懂 → 游戏玩得越好 → 金币越多 → 排名越高。** 这条因果链让"想赢钱"反过来拉着人去学。

## 1. 金币经济（Coins）

### a) 金币是什么，和 XP 怎么分工

产品里有**两种数值**，各管一摊，互不替代：

| 数值 | 管什么 | 怎么赚 | 能不能花 | 会不会清零 |
|------|--------|--------|---------|-----------|
| **XP（掌握度）** | mascot 成长 / L0–L4 等级 / 真实学到多深 | **只**靠完成 mission + 复习（学习行为） | 不能花，只升级 | **永不清零**（永久掌握度） |
| **金币 Coins 💰（财富）** | 财富榜 / 称号 / 装扮商店 / 护盾 | 学课程 **+** 玩游戏 **+** 应用知识 | 可花在**纯装饰**（见 §1c） | 累计金币永久；**"本周金币"每周一重置**（只重置比赛，不清身家） |

> 为什么分两套：**XP 不能被游戏刷**（保护"掌握度"的纯洁，防注水），**金币才是经济/社交货币**。
> 这样既满足你"赚钱当 leader"的诉求，又不破坏现有 XP/mascot 体系（`FRAMEWORK.md` §7）。

### b) 赚金币的两条路（都要"懂"才赚得多）

| 来源 | 给多少金币 | 关键：和"学懂"挂钩 |
|------|-----------|-------------------|
| **完成课程** | 每关基础金币 + **首次通关 / 满分 / 讲回来正确**额外加成 | 不是"点完就给"——加成靠真懂（满分、explain-back 正确） |
| **复习（SRS）** | 到期复习答对给金币（间隔越长答对越值钱） | 奖励"记住了"，对抗遗忘 |
| **玩游戏** | 见 §2/§3，**按表现结算**（技能/知识决定上限） | 学过对应概念 → 解锁更强的"招"→ 赢更多（§3） |

> **结算是确定的**：同样的操作拿同样的金币——**不是老虎机式随机掉落**。偶尔的"今日金币 ×2"惊喜可以有
> （`ENGAGEMENT.md` §1 多变奖励），但**节制、且对孩子尤其克制**（§7）。

### c) 金币花在哪（只有"纯装饰"出口，杜绝 pay-to-win）

金币的**唯一去向是装饰与温和的便利**，**绝不能买"学习内容"或"游戏胜利"**：

- 🦤 **mascot 装扮 / 动物园装饰**（皮肤、帽子、My Zoo 布景）——强化"这是我自己的"投入感。
- 🛡️ **Streak 护盾**（`ENGAGEMENT.md` §2b）——攒金币换护盾，给断签台阶下。
- 🎨 **称号外框 / 徽章皮肤**（纯展示）。

> **红线：** 金币**不能**用来跳关、解锁课程、买游戏胜利、买金币（无真钱入口）。
> 学习永远免费、永远不被金币卡住（§7）。

## 2. 游戏厅（Games Tab）— 1 分钟金融小游戏

像数学 app 有 Cross Math / Math Paths / Cash Dash / Magic Square 那样，做一个**独立的「游戏厅」Tab**，
放一组**~1 分钟、即开即玩、赢金币**的金融小游戏。**每款都是某个数学游戏的金融化版本**，
且**靠技能/知识取胜，不靠运气**。

| 游戏（暂名） | 对标数学游戏 | 玩法（~60s） | 教 / 用到的概念 | 门禁（学过才玩得好） |
|------|------|------|------|------|
| **预算十字 Budget Cross** | Cross Math | 在格子里填数，让每行/列满足 `收入 − 支出 = 储蓄`；高阶版让 `资产 = 负债 + 权益` 配平 | 储蓄率、预算、报表勾稽 | M1.1 储蓄率 → M4.1 三张报表 |
| **复利路径 Compound Path** | Math Paths | 从起点选一条路走到终点，沿途的选择让本金增值，凑到目标金额；越懂复利越会"早投/避高费率" | 复利、72 法则、费率侵蚀 | M0.3 复利与增长 |
| **现金冲刺 Cash Dash** | Cash Dash | 限时滑动：抢**更划算**的那笔（比单价）、躲开冲动消费/订阅蠕变陷阱、按期望值取舍 | 比价/单价、聪明消费、期望值 EV | M1.3 期望值、消费陷阱 |
| **魔方账本 Magic Ledger** | Magic Square | 把配置填进方阵，使每行/列/对角的**配置加起来 = 目标**（如四分法 100% / 组合权重） | Spend·Save·Give·Invest 四分法、分散配置 | M3.2 分散与 MPT |

**设计原则（每款都遵守）：**
- **技能门禁，不是运气：** 成绩由"你懂不懂 + 手快不快"决定，**没有随机抽奖式的输赢**（§7 防火墙）。
- **未学先玩也行，但天花板低：** 没学过对应概念也能瞎玩拿基础分；**学过 → 解锁更优策略 → 金币上限更高**——
  这正是"赢钱反向拉人去学"。
- **内容即数据：** 每款游戏是一个声明式配置（`requires` 概念 + `payout` 公式 + 60s 时限），
  新关卡/新难度由数据生成，不写新代码（`ARCHITECTURE.md` §3，见 §8）。

## 3. 每日游戏：每日市场 The Daily Market（旗舰，主线知识=战力）

> 你要的"**一个每天都能玩、且需要学到主线知识才能玩好的游戏**"——这是它。**产品的每日心跳。**

- **每天一局、~2 分钟、当天全员同一道题**（像 Wordle 的每日同题，可比、可晒）。
- **核心机制——"知识就是招式"：** 一局里你要对一笔钱做决策（怎么分配/投/避坑）。
  **你学过的主线概念，会变成你能用的"招"：**

| 你学过的主线（money-and-markets 承重概念） | 在每日市场里解锁的"招" |
|------|------|
| M0.2 **TVM** / M0.3 复利 | 能选"早投 + 复利"，把本金滚起来 |
| M1.1 储蓄率 / M1.3 期望值 | 能识别正期望值的机会、避开负 EV 陷阱 |
| M3.2 **分散** | 能把钱铺开降低波动，避免被一次坏运气清零 |
| M2.3 债券 / 价格-收益率 | 利率变动时能反向操作不踩雷 |

- **没学过主线 → 只能瞎选，金币少；学过越多 → 招越多、决策越稳 → 金币越多。** 这就是"**需要学到主线知识才能玩好**"。
- **技能而非运气：** 行情是**当天固定的同一道题**，赢的是"你的决策质量"，不是手气（§7）。
- **每日游戏的金币直接喂本周财富榜**（§4），是每天回来的最强钩子（`ENGAGEMENT.md` §2 习惯回路）。
- **连续参与**给"每日市场 streak"，但**断了不惩罚、有护盾**（亮模式）。

## 4. 财富榜（Wealth Leaderboard）— 谁这周赚得最多

把 `ENGAGEMENT.md` §4 的**小组联赛**直接复用，只把排名指标从 XP 换成 **本周金币**——
对金融 app 来说，"比谁这周赚得多"主题更贴、动力更强。

- **周榜 = 本周金币排名**（每周一重置比赛，**不清身家**：累计金币/称号/mascot/XP 全部永久保留）。
- **照搬全部护栏（这是底线，不可省）：**
  - 小组队列（~15–30 人）+ **升降级**，人人有够得着的目标。
  - **按活跃度配对**，避免"卷王碾压新手"。
  - **永远保留"个人最好"**：和自己比（"我的最高周收入"），排行榜**可一键关**——对孩子尤其重要。
  - **好友榜 / 家庭榜**（关系归属，SDT）：给队友点赞/加油，不做羞辱式公开比较。
- **周冠军**得一个**限定王冠/称号**挂一周（荣誉，非金钱），下周重新开战（fresh-start）。

> ⚠️ 排行榜的暗面（打击垫底者）在 `ENGAGEMENT.md` §4/§6 已有对策——**全部继承**。
> "最有钱=leader"只作为**正向荣誉**，绝不演变成"垫底羞辱"。

## 5. 动态 Feed — 谁学了几天、学了什么

一个**激励向的动态流**，让大家看见彼此在学、被带动着一起"学得多、赚得多"。

- **能上 feed 的（白名单，全是正向事件）：**
  "🔥 小明 连续学习 12 天"、"🎓 小红 学完了《复利与时间》"、"💰 阿杰 这周赚了 1,200 金币"、
  "🥚→🐣 你的 Emu 破壳了"、"🏆 周冠军诞生"。
- **亮模式（沿用 `ENGAGEMENT.md` §6）：** 只发**成就/进步**，**绝不发**"谁又没学/谁垫底/谁掉了 streak"——
  没有卖惨、没有羞辱、没有施压。
- **复用 Investment + relatedness：** 看见朋友进步 → 想跟上（社会认同），同时强化"这是我自己的成长"。
- **儿童保护（重点）：** 9 岁用户走**家庭模式**——feed 只在**家人/已知好友**范围内，**默认不公开**，
  可一键关；不向儿童推陌生人攀比。可分享内容由白名单约束，杜绝任意文本。

## 6. 称号与徽章 — 以"财富"为标尺

你要的"**赚钱多 = leader**"，做成一条**财富称号阶梯**，与现有 tier badge（按 XP）**并存、不替代**：

| 体系 | 按什么 | 例子 |
|------|--------|------|
| **进阶 Tier badge（已有）** | 累计 **XP**（掌握度） | 🥉Bronze → 🥈Silver → 🥇Gold → 💎Diamond（`ENGAGEMENT.md` §5） |
| **财富称号（本文新增）** | 累计 **金币**（财富） | 小会计 → 储蓄达人 → 精明消费者 → 复利大师 → … → **财富自由** |
| **周冠军王冠** | 本周金币第一 | 👑 限定一周的荣誉外框 |
| **里程碑 / 惊喜 badge（已有）** | 节点 / 不可预期 | 第一笔金币、连续完美、节日限定（`ENGAGEMENT.md` §5） |

- **两条线并行**讲两件事：tier badge = "你学得多深"，财富称号 = "你（在游戏经济里）多富"。两者都**可展示**（个人主页/分享）。
- **称号靠累计金币（长期）**，**周榜靠本周金币（短期竞技）**——长期成长与每周比赛分开，避免一时落后就否定积累。

## 7. 伦理护栏 — 怎么和现有 kid-safe 设计不打架

> 你的新诉求（赢钱小游戏 + 财富榜 + "最有钱=leader"）天然有"赌博/攀比"的味道；
> `ENGAGEMENT.md` §4/§6 又明确反对"终局排行榜"和操纵式游戏化。**下面是把两者焊住的防火墙。**

1. **防赌博防火墙 = 技能/知识，不是运气。** 所有"赢金币"的结果**由你的掌握度与决策质量决定**
   （同题同操作同结果），**没有随机抽奖、没有老虎机、没有幸运转盘**。赢靠"学懂了"，不靠手气——这从根上**不是赌博**。
2. **永远是虚拟金币，永不真钱。** 不可充值、不可提现、无真钱入口 → 无支付牌照、无博彩监管、无"付费坑娃"。
3. **学习永远免费、永不被金币卡住。** 金币是学习**下游**的庆祝与装饰经济；**绝不**出现"花金币才能继续学/解锁课程"。
   这条守住，金币就只会**激励**学习，不会**勒索**学习。
4. **只有装饰 sink，杜绝 pay-to-win。** 金币只买装扮/护盾/外框（纯展示），买不到学习内容、买不到游戏胜利（§1c）。
5. **继承全部留存护栏：** 小组联赛 + 升降级 + 同水平配对 + **永远的"个人最好"** + 排行榜/feed **可一键关** + 断签不罚（`ENGAGEMENT.md` §4/§6）。
6. **儿童特别保护：** 家庭模式、feed 限好友/家人且默认不公开、不向孩子推不可预测的上瘾式奖励、通知给家长不直接催孩子。
7. **反刷分：** 金币影响榜单，**必须服务端校验**，不能只信端上（`ENGAGEMENT.md` §7）。游戏成绩、金币结算在后端复算。

> 判断标准（沿用 `ENGAGEMENT.md` §6）：**"如果用户看穿了这个机制，他会感谢我们，还是觉得被耍了？"**
> 这套设计经得起看穿——因为它真的把"想赢"导向了"去学"。

## 8. 数据模型（内容即数据）

复用 `ARCHITECTURE.md` §3 "内容即数据 + zod 校验"，**新增两处，不发明并行结构**：

**① reward 字段加 `coins`**（现有是 `{xp, mascotGrowth}`）：
```json
"reward": { "xp": 120, "coins": 40, "mascotGrowth": true }
```

**② 新增 `game` 内容类型**（游戏厅 + 每日市场都用它，声明式）：
```json
{
  "id": "game.compound-path.d1",
  "kind": "game",
  "template": "compound-path",        // 对应一款玩法引擎
  "timeLimitSec": 60,
  "requires": ["money.m0.compound"],  // 学过这些概念 → 解锁更优策略/更高金币上限
  "payout": { "base": 10, "perScore": 2, "maxCoins": 120 },  // 按表现确定性结算
  "daily": false                      // 每日市场为 true（当天全员同一 seed）
}
```
- **`requires`** 把"学懂"接到"玩得好"：未满足只能拿 `base`，满足后解锁高分策略。
- **`payout` 是确定函数**（成绩→金币），**非随机**——这是 §7 防赌博的技术落点。
- **每日市场** `daily:true` + 固定 `seed`，保证"当天同题、可比、可晒"。
- **服务端复算 `payout`**，端上只渲染，防刷分（§7.7）。

## 10. 诚实边界

- **这是设计文档，不是代码**（`learning-os/` 仍在内容/设计阶段，符合"先做深、再写工程"）。
- **经济数值要靠 playtest 调**：金币产出/消耗、payout 曲线、护盾价格——**我不能凭空保证平衡**，需小范围试玩迭代。
- **儿童适配 + 攀比/财富叙事**面向真实孩子上线前，**建议找教育者/家长过一遍**（"以财富排名"对孩子的影响要谨慎评估）。
- **"技能非运气"是承诺也是约束**：实现时每款游戏都要复核"输赢是否真由掌握度决定"，**任何随机掉落都要克制并对孩子关闭**。
- **不夸大**：我不做"直接发社媒/保证流量数字"这类承诺；feed/榜单只是产品内机制。
