## 1. 一页结论（给创始人）

### 1.1 头号风险（按严重程度排序）

1. **麦克风类功能是最大的法律风险源。** 涉及家长手表的音量提醒和孩子端用声音检测练习。即使"不存音频"，只要拾音时间长、离开设备、被转写或做了说话人识别，就可能触发以下规则：美国联邦和各州的窃听或录音法（加州 Penal Code §632 要求所有当事人同意，民事赔偿每次 $5,000）、COPPA（儿童声音属于个人信息）、Apple 指南 2.5.14（录制必须明确同意并有可见提示）、Google Play 的监控类应用政策，以及中国《民法典》第1033条和《未成年人保护法》第63条。
   - **缓解思路：** 只算音量幅度（dB）或者做设备端的"有无琴声"分类；不转写、不识别说话人、不缓存超过几秒；不上传、不写日志；由用户主动开始或结束；全程有可见指示。
2. **孩子数据加大模型（LLM）：**
   - 美国：COPPA 要求可验证的家长同意（VPC）；2025 年修订后的规则已于 **2026-04-22** 进入合规期 〔待核实·高〕。Apple 5.1.2(i) 要求**明确告知并取得明确许可**，才能把个人数据给第三方 AI 〔已核实〕。
   - 美国州法与欧盟：加州 SB 243（陪伴型聊天机器人）〔待核实·中〕，欧盟 AI Act 第 50 条透明度义务 〔待核实·中〕。
   - 大模型 API 条款：多数对未成年人使用有限制 〔待核实·中〕。
   - 中国：涉及生成式 AI 的备案、登记或安全评估，以及显式标识；Apple 中国区要求申报 AI 功能并提交大模型或算法备案信息 〔已核实〕。
   - **建议：** v1 先用规则题库，不接 LLM，中国版尤其如此。
3. **"健康或心理"定性和宣传用语：**
   - 美国 FDA 一般健康（general wellness）政策与医疗器械软件的边界。
   - 中国 NMPA 医疗器械定义，以及《广告法》第17条（非医疗器械不得涉及疾病治疗功能）。
   - Apple：新 App 若属于 Health & Fitness 类别，需要申报"是否受监管医疗器械" 〔已核实〕。
   - Google Play 健康声明：应选"压力管理、放松、心智敏锐"（Stress management, relaxation, mental acuity），**不要**选"心理与行为健康"（Mental and behavioral health）〔已核实选项列表〕。
4. **健康数据泄露或共享的责任：**
   - FTC 健康泄露通知规则（Health Breach Notification Rule, HBNR）：向广告或分析 SDK 未授权披露也算"泄露" 〔待核实·高〕。
   - 华盛顿州 My Health My Data Act：没有营收门槛，有私人诉权 〔待核实·高〕。
   - HealthKit 数据不得用于广告，不得卖给数据经纪商 〔已核实〕，**不得存入 iCloud** 〔已核实〕。
5. **年龄验证与家长同意已经成为"平台加州法"的硬件要求：**
   - 德州 SB 2420：禁令解除后，Apple 自 **2026-06-04** 起对新账户执行 〔已核实〕。
   - 犹他：**2026-05-06** 起；路易斯安那：**2026-07-01** 起 〔已核实〕。
   - 开发者需要接入 Declared Age Range API、PermissionKit 的 Significant Change API 和 App Store Server Notifications；Google 侧对应 Play Age Signals API 〔已核实〕。
6. **分享给老师或教练、每周小结**属于"向第三方披露"儿童信息：
   - 美国 COPPA：未满 13 岁需要家长同意。
   - 中国 PIPL 第23条：单独同意，未满 14 岁还需监护人同意。
   - 英国 AADC 标准 11：孩子被监看时要有明显提示。
   - 13–17 岁孩子的自主权：设计上应默认"孩子主导分享"。
7. **中国大陆是一个结构性项目，不是简单"再上一个区"：**
   - 需要境内主体。
   - APP备案号：App Store 中国区必须填写并与工信部备案信息一致 〔已核实〕。
   - 数据境内存储。境外团队远程访问也算出境；未满 14 岁信息全部是敏感个人信息，**没有出境豁免门槛** 〔待核实·高〕。
   - 每年做一次未成年人个人信息合规审计 〔待核实·高〕。
8. **试点研究：** Apple 5.1.3(iii)(iv) 规定，开展健康相关人体研究的 App 必须取得知情同意（未成年人由家长或监护人同意），并取得**独立伦理审查委员会批准** 〔已核实〕。

### 1.2 能大幅降低风险的简化选择（建议写进 v1 范围）

| 决策 | 建议 | 原因 |
|---|---|---|
| 首发市场 | 先上**美国**（可加英国），其他 App Store 区域先不开放 | 每多一个法域就多一套儿童法；Apple 和 Google 都支持按国家设置可用性 |
| LLM | **v1 不接**：用人工编写的苏格拉底题库加规则分支 | 避开第三方 AI 共享同意、供应商未成年人条款、SB 243、中国生成式 AI 备案和标识 |
| 声音检测 | **练习检测以动作和手动计时为主**，声音只做可选的"设备端琴声或无声"分类 | 显著降低录音法风险 |
| 音量提醒 | 只取音量包络（RMS dB），设备端实时计算，**不存不传** | 不获取"通信内容" |
| Apple 儿童类别（Kids Category） | **不进入**，但按儿童类别的隐私标准做（不放第三方分析或广告 SDK） | 6–18 岁跨度大，儿童类别最高只到 9–11 岁档，且一经批准不可更改 〔已核实〕 |
| 三方 SDK | 不用广告 SDK，不用第三方分析或会话录制 SDK，崩溃报告也用第一方或明确适合儿童的方案 | 同时满足 COPPA、HBNR、Apple 1.3/5.1.4、Play 家庭政策，并降低加州 CIPA 诉讼风险 |
| 健康数据同步 | 不用 iCloud/CloudKit 存任何健康派生数据 | Apple 5.1.3(ii) 明文禁止 〔已核实〕 |
| Samsung | v1 用标准 Wear OS 接口（Health Services、SensorManager、麦克风），**不用 Samsung Health Sensor SDK** | 避开 Samsung 合作伙伴审批 〔待核实·中〕 |
| 中国 | 中国版在 v1 后单独立项：境内主体、境内云、无 LLM | 见第 7 节 |

## 3. 对照：如果产品持续录制孩子与朋友的对话，会发生什么？

**目的：让创始人理解"不录朋友或旁人"这条线为什么存在。** 一句话：**家长的同意无法替朋友（以及朋友的家长）同意。** 持续录制会让同一个违法行为按"人数 × 次数"累计，平台也会直接拒审或下架。

### 3.1 美国

| 法律或规则 | 触发点 | 后果 | 标签 |
|---|---|---|---|
| 联邦《Wiretap Act》，18 U.S.C. §2511 | 用设备截获他人的"口头通信"。联邦是一方同意制，但当佩戴者**不是对话一方**（例如旁边朋友之间的对话），或者孩子本人无法有效同意时，就没有任何一方同意 | 刑事责任（最高 5 年）；民事赔偿取"每天 $100"和 $10,000 中较高者，外加惩罚性赔偿和律师费（§2520）；§2512 还禁止制造或销售主要用于秘密截获的设备 | 〔待核实·高〕 |
| "代理同意"原则（vicarious consent） | 部分法院（例如 *Pollock v. Pollock*，第六巡回法院，1998 年）允许父母出于子女最佳利益、在善意且客观合理的情况下代子女同意 | **只覆盖自家孩子，不覆盖朋友**；各州态度不一；产品化的全天录制很难被认为"必要" | 〔待核实·中〕 |
| 加州 Penal Code §632（Invasion of Privacy Act） | 未经**所有当事人**同意，用录音设备窃听或录制"保密通信"（当事人有客观合理期待，不希望被旁听或录音） | 刑事：每次最高罚款 $2,500（有前科最高 $10,000），可处一年以下监禁；民事（§637.2）：每次 $5,000 或三倍实际损失，**不需要证明实际损失**，很适合集体诉讼 | 〔待核实·高〕 |
| 其他"所有当事人同意"州 | 常见列表：加州、佛罗里达、伊利诺伊、马里兰、马萨诸塞、蒙大拿、新罕布什尔、宾夕法尼亚、华盛顿州；俄勒冈（面对面对话）；康涅狄格（电话，民事）；内华达和密歇根有争议 | 刑事加民事 | 〔待核实·中〕 |
| 学校场景 | 加州 Education Code §51512：未经教师和校长事先同意，任何人（包括学生）在中小学教室使用电子监听或录音设备均属违法（轻罪）。其他州或学区多有类似规定 | 孩子戴着设备去上课就可能违法 | 〔待核实·高〕 |
| COPPA（16 CFR Part 312） | 朋友若未满 13 岁，其声音录音属于"个人信息"；运营者无法取得朋友家长的 VPC | FTC 或州检察长执法，按违规次数计民事罚款（2025 年通胀调整后约每次 $53,088）。先例：2023 年 Amazon Alexa 因留存儿童语音等问题支付 $25M 民事罚款 | 〔待核实·中〕 |
| 伊利诺伊 BIPA（740 ILCS 14） | 若为区分家长和孩子而做"说话人识别"，生成**声纹**（voiceprint） | 每人 $1,000（过失）或 $5,000（故意）；2024 年修订后按人计一次 | 〔待核实·高〕 |
| FTC 法第5条或州 UDAP 法 | 宣传"不录音"但实际在录，或通过日志或崩溃报告带出音频 | 欺骗性行为执法 | 〔待核实·高〕 |
| Apple 2.5.14 | 录制或记录用户活动（含麦克风）必须**明确同意**，并有**清晰的视觉或声音提示** | 拒审或下架 | **〔已核实〕** developer.apple.com/app-store/review/guidelines/ |
| Google Play 监控类应用政策（Stalkerware） | 监控他人的应用只有"专为家长监护或企业管理设计和宣传"时才算合法，且必须有持续通知、独特图标、`isMonitoringTool` 元数据标记和商店描述披露；隐蔽监控一律禁止 | 拒审、下架、封号 | 〔待核实·高〕（政策页被拦截） |

### 3.2 欧盟/英国

- **GDPR：** 朋友是数据主体，没有合法基础（第6条）。"纯家庭活动"豁免只适用于个人本身，**不适用于提供服务的公司**。罚款最高可达 €20M 或全球营业额 4%（第83(5)条）〔待核实·高〕。大规模监控加上儿童，必须做 DPIA（第35条）。
- **英国：** UK GDPR 加 ICO《Age Appropriate Design Code》。其中"联网玩具和设备"与"家长控制"标准（第14、11条）要求孩子知道自己正被监看 〔待核实·高〕。
- **欧盟 AI Act：** 若产品从声音中"识别情绪"并用于**教育机构**，属于第5(1)(f)条禁止的做法（2025-02-02 起适用）〔待核实·中〕。

### 3.3 中国大陆

- **《民法典》第1032、1033条：** 未经权利人明确同意，不得"拍摄、窥视、窃听、公开他人的私密活动"，不得"处理他人的私密信息" 〔待核实·高〕。
- **《未成年人保护法》第63条：** 除法定情形外，任何组织或个人不得开拆、查阅未成年人的信件、日记、电子邮件或其他网络通讯内容。父母可以代**无民事行为能力**（未满 8 周岁）的子女查阅；其余情形仅限国家安全、刑事侦查或紧急人身安全 〔待核实·高〕。这意味着即使是父母，对 8 岁以上孩子的通讯内容也受限。
- **PIPL：** 朋友的声音属于个人信息；朋友未满 14 岁时属于**敏感个人信息**（第28条），需要其监护人同意（第31条）加单独同意（第29条），实际上无法取得。罚则最高 5000 万元或上一年度营业额 5%（第66条）〔待核实·高〕。
- **刑事与治安责任：**
  - 《刑法》第253条之一（侵犯公民个人信息罪）。按 2017 年"两高"司法解释，非法获取"通信内容"等 50 条以上即属"情节严重" 〔待核实·中〕。
  - 《刑法》第283、284条（非法生产、销售、使用窃听专用器材）。若设备被认定为窃听专用器材，后果严重 〔待核实·中〕。
  - 《治安管理处罚法》中的偷窥、偷拍、窃听、散布他人隐私条款（2025 年修订版条号待核实）。

**结论：** 持续录制朋友对话，在美国、欧盟和中国都可能同时触发刑事、民事、监管和平台四类后果。**设计层面的红线应写进技术规格：设备端实时处理；只输出非内容型结果（音量、是否有琴声、时长）；音频帧不落盘、不上传、不进日志。**

### 4.2 开发者计划注册（个人与组织、D-U-N-S、费用）〔已核实〕

来源：https://developer.apple.com/programs/enroll/ 和 https://developer.apple.com/support/D-U-N-S/ （2026-11-21）

- **个人：** 法定姓名，账户开启双重认证，达到当地成年年龄；商店上显示个人姓名作为卖家名。
- **组织（建议采用，理由见 5.1.1(ix)）：**
  - 必须是能签合同的**法人实体**，不接受 DBA、虚构商号、商号或分支机构。
  - 注册人必须有代表公司签约的权限（所有者、高管，或获得授权的员工）。
  - 必须提供 **D-U-N-S 编号**（政府机构除外）。
  - 必须有与组织域名一致的工作邮箱，以及**公开可访问、内容完整**的官网（社交媒体页或空壳页面不被接受）。
- **D-U-N-S：** 由 D&B 免费分配。申请后最多需要 **5 个工作日**（加急不会缩短）；拿到编号后，Apple 还需最多 **2 个工作日**同步 D&B 数据；超过两周可以邮件联系 D&B。D&B 记录为"个人独资"时，只能以个人身份注册。
- **费用：** **每个会员年 99 美元**，各地区按当地货币显示；非营利组织、认证教育机构和政府机构可以申请减免。中国区价格为人民币 688 元/年 〔待核实·高：页面只写"价格可能因区域而异"〕。
- **中国大陆的组织：** App Store 中国区产品页会自动显示 D-U-N-S 档案里的**中文公司名**和**统一社会信用代码**（依据《反电信网络诈骗法》和《网络安全法》）〔已核实〕。https://developer.apple.com/help/app-store-connect/manage-compliance-information/view-china-mainland-compliance-information
- 中国开发者在 App Store Connect 需要补充**国务院令第810号**（《互联网平台企业涉税信息报送规定》）所需的信息，Apple 每季度向国家税务总局报送 〔已核实〕。

### 4.3 TestFlight 〔已核实〕

来源：https://developer.apple.com/testflight/

- 内部测试员最多 100 名，需在团队中担任特定角色。
- 外部测试员最多 10,000 名。外部测试的**首个构建版本必须通过 App Review 的 beta 审核**，加入测试组后会自动提交。
- 最多可分享 100 个构建版本；每个测试员最多 30 台设备；支持公开链接，并可按设备和系统版本设置门槛。
- 构建版本 90 天后过期 〔待核实·高：本页未写〕。
- DPLA 规定：TestFlight 不得向测试员收费，应用内数字购买在 beta 期间必须免费 〔已核实〕。
- **儿童试点注意：** 外部测试员如果是孩子，COPPA 和研究伦理要求照样适用（见第 9 节）。TestFlight 不是合规豁免。

### 4.4 审核时长与加急 〔已核实〕

来源：https://developer.apple.com/distribute/app-review/

- App Review 全天候运行，"通常至少 **50%** 的提交在 **24 小时内**审完，**90%** 在 **48 小时内**审完"。
- 遇到关键 bug 修复或与活动相关的发布，可以申请**加急审核**。对审核结果不服时，可以向 App Review Board 申诉（每次提交只能申诉一次）。
- 经验上，涉及健康、儿童或 AI 的新 App 常常要来回几轮。建议在计划里预留 **1–3 周**。这是经验估计，不是官方数字。

### 4.5 watchOS 要求 〔已核实〕

- **SDK 最低要求：** 自 **2026-04-28** 起，上传到 App Store Connect 的 App 必须用 **Xcode 26** 或以上版本、基于 watchOS 26 等 SDK 构建。自 2026-09-09 起，iOS App 必须以 iOS 13 或以上为部署目标。来源：https://developer.apple.com/news/upcoming-requirements/
- **独立运行：** Apple 建议 watchOS App 不依赖 iPhone 也能使用。可以做纯手表 App，或者带 iOS 伴侣 App，两者内购通用。来源：developer.apple.com/documentation/watchos-apps/creating-independent-watchos-apps
- 新项目采用**单 target** 结构；最低部署版本为 watchOS 9.2 及以上时，旧的双 target 结构会编译报错。
- **Family Setup（儿童手表）：** 孩子用的、经家长 iPhone 设置的 Apple Watch 能否安装第三方 App、HealthKit 是否可用、数据能否同步，需要真机实测 〔待核实·低〕。v1 的手表端只面向**家长**，可以绕开这个问题。

### 4.6 HealthKit 授权与条款 〔已核实〕

来源：developer.apple.com/documentation/healthkit（setting-up、protecting-user-privacy、authorizing-access）和 DPLA。

- 在 Xcode 中开启 HealthKit 能力。不需要时**不要勾选 Clinical Health Records**，否则可能被拒。
- 读和写分别需要用途说明字符串（`NSHealthShareUsageDescription` 和 `NSHealthUpdateUsageDescription`），缺少会导致崩溃。
- 用户可以按数据类型分别授权读或写，App 无法得知自己被拒绝读取；用户还可以只授权最近一段时间的数据。
- **使用限制（DPLA 3.3.3(H) 和文档）：**
  - 只能用于健康、运动或健身目的，并且要在营销文案和界面上体现。
  - 不得用于广告。
  - 未经用户明确同意不得披露给第三方，且只能给同样提供健康服务的第三方。
  - **不得出售**给广告平台、数据经纪商或信息转售商。
  - 经用户同意，可以共享用于医学研究。
  - **必须提供隐私政策。**
- 用于人体研究，或用于 HealthKit 临床健康用途时：必须告知用途并取得参与者或**其监护人**的同意；必须禁止接收去标识化数据的第三方进行再识别（DPLA）。
- 建议：呼吸练习写入 `mindfulSession`（正念分钟）；v1 **不读取**心率等数据。若要读取，先评估 HBNR 和 MHMDA 的影响。

### 4.7 年龄验证与家长同意 API（德州、犹他、路易斯安那）〔已核实〕

来源：developer.apple.com/news（2025-10-08、2025-11-04、2025-12-23、2026-02-24、2026-06-03 的公告）

- **德州 SB 2420：**
  - 原定 2026-01-01 生效；2025-12-23 地区法院发出禁令后，Apple 暂停了部署。
  - 2026-06-03 Apple 公告"法院裁决解除禁令"，自 **2026-06-04** 起，德州新的 Apple 账户受该法约束：未满 18 岁的下载、App 内购买和 App 的"重大变更"都需要年龄确认和家长同意，家长也可以撤回同意。
  - 年龄分档：未满 13、13–15、16–17、18 岁以上。
- **犹他：** **2026-05-06** 起的新账户；**路易斯安那：** **2026-07-01** 起的新账户。开发者请求时，系统会通过 Declared Age Range API 返回年龄分档。
- **开发者需要实现：**
  1. **Declared Age Range API**：获取年龄分档、年龄确认方式，以及当地是否有监管要求。
  2. **PermissionKit 的 Significant Change API**：由开发者自行判断何为"重大变更"，判定后请家长重新同意。在德州，**年龄分级变化本身就算重大变更**。
  3. **StoreKit 的新年龄分级属性**。
  4. **App Store Server Notifications**：接收家长撤回同意的通知。
- **DPLA 3.3.3(O)：** 年龄分档数据只能用于提供适龄内容或满足法律要求，不得出售或分享给数据经纪商。
- **PermissionKit** 还能让孩子请求家长批准"与他人沟通"，可以用于"分享给老师"前的家长审批。来源：developer.apple.com/app-store/kids-apps/
- 其他地区：巴西、澳大利亚、新加坡有 18+ 下载限制；巴西会返回年龄分档。

### 4.8 年龄分级问卷（2025–2027 的变化）〔已核实〕

- 新分级体系包括 4+、9+、13+、16+、18+。新问题涵盖 App 内控制、能力、**医疗或健康主题**、暴力主题。**AI 助手和聊天功能对敏感内容出现频率的影响必须计入分级。**
- **社交媒体能力**问题：2026 年 9 月起提交时必答。有社交媒体能力的 App 最低为 13+，除非对 13 岁以下关闭（此时需要至少用 Declared Age Range 检查年龄）。我们的"分享给老师"是一对一分享，应如实评估是否属于"社交媒体能力"（定义是通过信息流或类似发现机制再分发、放大用户内容）。按定义大概率**不属于**，但应保留判断记录。
- **新内容描述项（2026-11-16 起）：** "Shared Location"（共享位置）和 "Dating and Relationships"（含与"虚拟伴侣"的恋爱或性内容，直接 18+）。**所有 App 须在 2027-01-12 前填写完毕。** 若接 LLM，必须从技术上防止任何恋爱或性角色扮演。

### 4.9 受监管医疗器械状态申报 〔已核实〕

来源：https://developer.apple.com/help/app-store-connect/manage-app-information/declare-regulated-medical-device-status 和 2026-03-26 的公告。

- 在美国、欧盟/EEA 或英国分发，且主类别或次类别为 **Health & Fitness 或 Medical**，或者年龄分级里"医疗或治疗信息"选了"频繁"的 App，必须申报是否属于受监管医疗器械。
- **新 App 自 2026-03-26 起必填；存量 App 须在 2027 年初前补填。**
- 我们应选择 **No**。前提是产品和宣传都不涉及疾病的诊断、预防、监测或治疗（见第 6.6 节措辞表）。选 Yes 则需要 FDA Owner/Operator Number、使用说明、适应症声明和安全信息。

### 4.10 隐私"营养标签"与隐私清单

- App Store Connect 中需要填写 App Privacy（数据类型、是否关联身份、是否用于追踪）〔已核实帮助页存在〕。
- 使用"必须声明原因"的 API 时（包括第三方 SDK 中的调用），必须在隐私清单（privacy manifest）中写明原因，否则无法上传 〔已核实〕。

### 4.11 Apple 中国区（见第 8.9 节）

- **ICP 备案号：** 部分 App 必须有有效的 ICP 备案号（即 APP 备案号），并且 App 信息页的名称等元数据必须与工信部的备案一致（以简体中文本地化为准）〔已核实〕。
- **AI 生成或合成服务：** 必须申报，并提供**大模型或算法备案信息**；若使用他人的模型，还需提供**授权或使用协议**。若有"分发 AI 生成内容"等功能，需要提供**全国互联网安全管理服务平台的安全评估通过截图和报告（盖公章）**。所有中国区 App 都要完成这些申报（没有相关功能就选 No）；**存量 App 须在 2027-01-31 前完成** 〔已核实〕。

## 6. 美国法律

### 6.1 COPPA（Children's Online Privacy Protection Act；15 U.S.C. §§6501–6506；16 CFR Part 312）

**适用性：**

- 孩子端 App 面向 6–18 岁，属于"面向儿童"（directed to children）的服务，对**未满 13 岁**的用户适用 COPPA。
- 由于儿童不是唯一受众，可以按"混合受众"（mixed audience）处理：用中立的年龄筛查（不诱导谎报，可结合 Declared Age Range 或 Play Age Signals），只对未满 13 岁的用户执行 COPPA 流程。2025 年修订已把"混合受众"的定义写入规则 〔待核实·高〕。
- 家长手表 App 面向成人。设备端的音量计算如果**不存储、不上传、不识别个人**，运营者就没有"收集"儿童个人信息 〔待核实·中：这是法律解释，建议律师确认〕。

**2025 年修订规则**（FTC 2025-01-16 宣布；**联邦公报 2025-04-22 发布（90 FR 16918）**；**2025-06-23 生效**；**多数条款合规截止日为 2026-04-22，现已过期**）〔待核实·高〕：

1. **向第三方披露需要单独的 VPC：** 把儿童信息披露给第三方（如定向广告），除非披露是服务不可或缺的部分，否则需要单独取得家长同意。分享给老师是"服务功能"还是"第三方披露"，应按保守方式设计为**家长明示批准**。
2. **书面数据留存政策：** 只在合理必要期间内留存，**不得无限期保留**，并在隐私通知中公开。
3. **书面信息安全计划：** 指定负责人，至少每年做一次风险评估，测试与监控，并对服务商提出要求。
4. **个人信息定义扩大：** 新增**生物识别信息**（指纹、视网膜或虹膜、DNA、**声纹**、步态、面部模板等）和政府签发的身份证件号码。
5. **新增 VPC 方式：** 知识问答、证件与人脸比对（比对后删除），以及"短信加确认"（text plus，仅限不对外披露的情形）。"邮件加确认"（email plus）仍可用于仅内部使用的场景 〔待核实·中〕。
6. **家长通知要更具体：** 写明第三方的身份或类别、目的、留存政策等。
7. **安全港计划：** 透明度要求加强。
8. **未写入规则的提案：** FTC 没有采纳限制推送通知或"参与度优化"的提案，也没有把"学校授权"写入规则 〔待核实·中〕。

**其他要点：**

- 家长有权查看、删除、拒绝继续收集；不得以收集超出必要的信息作为参与条件（§312.7）〔待核实·高〕。
- 民事罚款按违规次数计算；2025 年通胀调整后约为**每次 $53,088**，2026 年金额待核实 〔待核实·中〕。州检察长也可以执法。
- 可以选择加入 FTC 批准的**安全港计划**（如 CARU、ESRB Privacy Certified、iKeepSafe、kidSAFE、PRIVO、TRUSTe），年费从数千美元起 〔待核实·中〕。
- 若接 LLM：孩子的自由文本输入属于个人信息（可能包含姓名、学校等）。LLM 供应商应以"服务提供商"身份签约：零留存或短留存、不用于训练、保密、安全，并取得书面保证（2025 年规则对服务商有书面保证要求）〔待核实·中〕。同时要满足 Apple 5.1.2(i) 的明确 AI 共享许可 〔已核实〕。

### 6.3 消费者健康数据法（容易被忽视的高风险）

- **华盛顿州《My Health My Data Act》（RCW 19.373）**〔待核实·高〕：
  - "消费者健康数据"定义很宽，包括身心健康状况、生理功能、生命体征、症状，以及**由非健康数据推断出的健康信息**。呼吸练习和压力管理都可能落入。
  - 收集要**单独同意**，共享要**另行单独同意**，出售需要书面授权；必须有单独的"消费者健康数据隐私政策"并在首页链接；禁止在医疗设施周边设地理围栏。
  - **没有营收门槛**，通过《消费者保护法》提供**私人诉权**。主体条款自 2024-03-31 起适用（小企业 2024-06-30）。
- 内华达 SB 370（类似，无私人诉权）和康涅狄格的健康数据条款 〔待核实·中〕。
- **建议：** 对全美用户统一采用华盛顿州标准的健康数据同意流程（收集、共享两次单独勾选），以及"消费者健康数据隐私政策"。

### 6.4 FTC Health Breach Notification Rule（16 CFR Part 318）

依据：2024 年修订版，联邦公报 2024-05-30（89 FR 47028），**2024-07-29 生效** 〔待核实·高〕。

- **适用对象：** 个人健康记录（PHR）供应商。PHR 指能从**多个来源**获取信息、由个人管理或主要为个人服务的电子记录。例如：用户手动输入加手表传感器，或加 HealthKit 或 Health Connect。规则明确涵盖健康 App。"健康服务"包括追踪**健身、睡眠、心理健康**等的在线服务。
- **"安全泄露"包括未经授权的披露**，不只是黑客攻击。例如，未经授权把数据发给广告或分析 SDK。
- **通知时限：**
  - 发现后无不当延迟，最迟 **60 个自然日**内通知个人。
  - 影响 **500 人以上**：同时通知 FTC；某州 500 人以上居民受影响时还要通知媒体。
  - 少于 500 人：在日历年结束后 60 天内向 FTC 报送。
- 民事罚款同样按次计算（约 $53,088 每次，2025 年）〔待核实·中〕。先例：GoodRx（2023 年，$1.5M）、Premom（2023 年）〔待核实·中〕。
- **建议：** 制定事件响应预案，包含 60 天时间线；SDK 白名单；数据流图。HIPAA 一般不适用（我们不是受监管实体或其业务伙伴），除非与医疗机构合作 〔待核实·高〕。

### 6.5 录音法、生物识别法

见第 3 节。我们产品的合规设计要点：

1. **音量提醒：** 只计算声压包络（例如每 0.5–1 秒算一次 RMS 或 dB），**不保存原始 PCM、不做语音识别、不做说话人识别**，阈值判断完立即丢弃。手表上要有"正在监听音量"的常驻指示（Apple 2.5.14）〔已核实〕。**默认关闭**，在设置里由家长主动开启，并说明"这会感知周围声音的响度，包括家人的声音"。
2. **声音检测练习：** 由孩子点击"开始练习"后启动，最长 N 分钟后自动停止；只在设备端输出"有琴声或无琴声"的时间片；**不上传、不留存音频**。在 Android 上必须使用麦克风前台服务并显示通知 〔已核实〕。
3. **工程防线：** 确保音频缓冲不会进入崩溃报告、调试日志或分析事件；发布前做抓包和代码审计，证明"无音频外传"。这是防止 FTC 第5条"欺骗性宣称"的关键。
4. 不做声纹，从而避开 BIPA、德州 CUBI、华盛顿生物识别法和 COPPA 中的生物识别定义。

### 6.6 FDA：一般健康产品与医疗器械软件

**依据** 〔待核实·高〕：

- FD&C Act §520(o)(1)(B)（2016 年《21st Century Cures Act》第3060条）：仅用于"维持或促进健康生活方式"、**与疾病或状况的诊断、治愈、缓解、预防或治疗无关**的软件功能，不属于器械。
- FDA《General Wellness: Policy for Low Risk Devices》（2016 年首发，2019 年修订）。据我所知，FDA 在 2026 年初对一般健康和临床决策支持指南做过更新，尤其涉及可穿戴设备的生理参数，需要核对最新原文 〔待核实·低〕。
- FDA《Policy for Device Software Functions and Mobile Medical Applications》（2022）。其中提到：**帮助已确诊精神疾病患者（如 PTSD、抑郁、焦虑、强迫症）维持应对技能**的 App **仍然是器械**，只是 FDA 行使执法裁量权 〔待核实·中〕。
- **这意味着**：只要写"帮助有焦虑的孩子"，产品性质就变了。

**一般健康的两类用途** 〔待核实·高〕：

1. 与特定疾病无关的一般健康，例如压力管理、放松、心智敏锐、自尊、睡眠管理、体能或健身。
2. 在已被充分认识的前提下，健康生活方式有助于降低某些慢性病风险或影响，而且必须这样表述。

v1 只用第 1 类。

**措辞对照**（中英文都要遵守，App Store、Play 商店页、官网、社媒、投资人材料都适用）：

| 可以用 | 避免使用 |
|---|---|
| pause、breathe、relax、calm down together、unwind | treat、cure、therapy、therapeutic、clinical、prescription |
| everyday stress management、build a pause habit | anxiety、depression、ADHD、autism、anger disorder、meltdown management for diagnosed conditions |
| practice log、track practice time、reflect | diagnose、detect / screen / assess mental health、monitor mood disorders、early warning |
| reminder to lower your voice（家长自用） | detect anger / emotion / abuse、measure stress level（若无验证） |
| supports family routines、encourages reflection | clinically proven、reduces symptoms、replaces counseling |
| "Not a medical device. Not intended to diagnose, treat, cure or prevent any disease." | "medical-grade""FDA-approved"（除非属实） |

另外：Apple 1.4.1 要求健康测量类宣称必须有验证 〔已核实〕。我们**不做"压力值""情绪值"这类数值输出**。

### 6.7 AI 相关（若接入 LLM）

- **FTC 第5条：** 对 AI 能力的夸大宣称、对未成年人的不公平做法都会被执法。FTC 在 2025 年就 AI 陪伴类聊天机器人向多家公司发出 6(b) 调查令 〔待核实·中〕。
- **供应商条款：** 主流大模型 API 的使用政策普遍对**未满 13 岁**用户禁用或附加条件，对未满 18 岁要求额外保护措施，例如年龄验证、内容过滤、家长同意、安全护栏。签约前逐条核对，并把义务写进我们的产品规格 〔待核实·中〕。
- **安全设计底线：**
  - 表明"我是 AI，不是真人"。
  - 不扮演治疗师，不扮演恋爱对象。
  - 识别到自伤或受虐信号时，给出预设的转介话术（如 988 热线、信任的成年人），并通知家长。家长通知要谨慎，涉及家庭虐待时可能适得其反，需要律师和儿童保护专家参与设计。
  - 不保存或尽量少保存对话；孩子可以删除；有举报按钮。

## 8. 中国大陆

> 中国政府网站（flk.npc.gov.cn、cac.gov.cn、miit.gov.cn、gov.cn、nmpa.gov.cn）全部被拦截。以下条文为〔待核实〕；其中 Apple 中国区的要求已从 developer.apple.com 核实。

### 8.1 《中华人民共和国个人信息保护法》（PIPL，2021-11-01 施行）

〔待核实·高〕

- **第3条第2款（域外适用）：** 以向境内自然人提供产品或服务为目的的境外处理，同样适用。境外处理者须在境内设立专门机构或指定代表（第53条）。
- **第28条：** **不满十四周岁未成年人的个人信息**与生物识别、医疗健康、行踪轨迹等一样，属于**敏感个人信息**。只有在有特定目的、充分必要并采取严格保护措施时才能处理。
  - **对我们的含义：** 6–13 岁孩子的**全部**信息都是敏感个人信息，包括昵称和练习时长。练习或呼吸数据还可能另外落入"医疗健康"。
- **第29条：** 处理敏感个人信息须取得**单独同意**。
- **第30条：** 还要告知处理的必要性和对个人权益的影响。
- **第31条：** 处理不满十四周岁未成年人的个人信息，须取得**父母或其他监护人的同意**，并**制定专门的个人信息处理规则**。
- **第23条：** 向其他个人信息处理者提供个人信息（例如分享给老师或教练），须告知接收方名称、联系方式、目的、方式和种类，并取得**单独同意**。
- **第38–39条：** 出境需要满足条件之一，并取得**单独同意**（见第 8.5 节）。
- **第55–56条：** 处理敏感个人信息、自动化决策、委托处理或对外提供、出境等情形，事前须做**个人信息保护影响评估**，记录至少保存 3 年。
- **第51–52、54、57条：** 安全措施；个人信息保护负责人（处理量达到规定数量时）；定期合规审计；事件补救与通知。
- **第66条罚则：** 情节严重的，最高 **5000 万元或上一年度营业额 5%**，可吊销执照，直接责任人员可被罚款并禁止任职。

### 8.2 《儿童个人信息网络保护规定》（国家互联网信息办公室令第4号，2019-08-22 公布，2019-10-01 施行）

〔待核实·高：条号可能有±1 的偏差〕

- "儿童"指**不满十四周岁**的未成年人。
- 须设置**专门的儿童个人信息保护规则和用户协议**，并**指定专人负责**。
- 收集、使用、转移、披露儿童个人信息，须以显著、清晰的方式告知监护人并征得同意。告知内容包括：目的、方式、范围；存储地点、期限及到期处理方式；安全措施；拒绝的后果；投诉渠道；更正和删除途径。同意时须提供**拒绝选项**。
- 不得收集与服务无关的信息；存储期限以实现目的所必需为限；须加密存储；内部访问最小授权并留有审批记录。
- 委托第三方处理须做**安全评估**并签订委托协议；向第三方转移须做安全评估。
- 监护人有权更正、删除；撤回同意后应删除。发生安全事件须告知并报告。

### 8.3 《未成年人保护法》（2020 年修订，2021-06-01 施行）与《未成年人网络保护条例》（国务院令第766号，2023-10-16 公布，2024-01-01 施行）

- **《未成年人保护法》**〔待核实·高〕：
  - 第72条：处理不满十四周岁未成年人的个人信息须征得监护人同意；未成年人或监护人要求更正或删除时须及时处理。
  - 第73条：发现未成年人通过网络发布私密信息时，应及时提示并采取保护措施。
  - 第74条：防沉迷；不得提供诱导沉迷的产品。
  - 第63条：通讯秘密，见第 3.3 节。
- **《未成年人网络保护条例》**（共七章，含"个人信息网络保护"和"网络沉迷防治"两章）：
  - **个人信息处理者应当每年自行或委托专业机构，对其处理未成年人个人信息的合规情况进行审计，并及时报告网信等部门**〔待核实·高：内容；条号约为第37条，待核实〕。

### 8.4 APP 备案（工信部）与 ICP

- **依据：** 《工业和信息化部关于开展移动互联网应用程序备案工作的通知》（工信部信管〔2023〕105号），以及《反电信网络诈骗法》和《互联网信息服务管理办法》（国务院令第292号）〔待核实·高〕。
- **时间线：** 自 2023 年 9 月起新 App"先备案后上线"；存量 App 须在 2024-03-31 前补备案；之后未备案的会被处置 〔待核实·高〕。
- **办理流程：** App 主办者通过**网络接入服务商**（即云服务商）或 **App 分发平台**提交，由省级通信管理局审核（一般不超过 20 个工作日）。提交材料包括：主体证件、负责人信息、App 名称、服务内容、包名或 Bundle ID、签名证书公钥或 MD5 等 〔待核实·中〕。
- **主体：** 备案主体一般须为**境内**单位或个人，境外公司不能直接作为主办者 〔待核实·中〕。
- **前置审批：** 涉及新闻、出版、教育、医疗保健、药品和医疗器械等互联网信息服务的，须先取得前置审批 〔待核实·中〕。
  - 若宣传为"教育类 App"并进入学校场景，可能还需要**教育移动应用备案**（教育部 2019 年教技函〔2019〕55号相关要求）〔待核实·中〕。**v1 不进校园**。
- **ICP 许可证：** 若 App 有付费订阅等**经营性**互联网信息服务，可能需要《增值电信业务经营许可证》（B25 类，即 ICP 证），而不只是备案。外资准入有限制，2024 年起部分地区开展了扩大开放试点 〔待核实·低〕。
- **Apple 侧** 〔已核实〕：中国区 App 须填写 ICP 备案号，且与工信部备案信息一致，核验通过后会在产品页展示。

### 8.5 数据出境

〔待核实·高，除另注〕

- **规则体系：**
  - 《数据出境安全评估办法》（2022-09-01 施行）。
  - 《个人信息出境标准合同办法》（2023-06-01 施行）。
  - 《促进和规范数据跨境流动规定》（国家网信办令第16号，2024-03-22 施行）。
  - 《个人信息出境认证办法》（2026-01-01 施行）〔待核实·中〕。
- **门槛（关键信息基础设施运营者以外的处理者，自当年 1 月 1 日起累计）：**
  - 不满 10 万人的**非敏感**个人信息：豁免。
  - 10 万至 100 万人的非敏感个人信息，**或不满 1 万人的敏感个人信息**：标准合同（备案）或认证。
  - 100 万人以上的非敏感个人信息，**或 1 万人以上的敏感个人信息**：安全评估。
  - 另有订立或履行合同所必需、紧急情况等豁免情形；自贸区可以有负面清单。
- **对我们的含义：**
  - 未满 14 岁的信息全部是敏感个人信息，**哪怕只有 1 个孩子的数据出境**，也至少要签标准合同、做个人信息保护影响评估、备案并取得单独同意。
  - **境外团队远程访问境内数据也属于出境。**
  - 还要满足 PIPL 第39条的告知和单独同意。
- **建议：** 中国版的数据**全部留在境内**（境内云和境内运维），境外团队不接触生产数据。也不要调用境外的分析、崩溃报告或大模型服务。
- **相关规定：**
  - 《网络数据安全管理条例》（国务院令第790号，2025-01-01 施行）：涉及个人信息处理规则、重要数据、处理 1000 万人以上个人信息时的负责人等 〔待核实·中〕。
  - 《个人信息保护合规审计管理办法》（2025-05-01 施行）：处理 1000 万人以上个人信息的，至少每两年审计一次 〔待核实·中〕。
  - 注意：《未成年人网络保护条例》的**未成年人**合规审计是**每年一次**，与人数无关 〔待核实·中〕。

### 8.6 软件著作权与国内安卓应用商店

- **软著：** 依据《计算机软件保护条例》和《计算机软件著作权登记办法》，向**中国版权保护中心**申请登记。官方登记费自 2017 年起停征 〔待核实·中〕。常规周期约 30–60 个工作日；代理加急可缩短到数天到两周，代理费从数百到数千元 〔待核实·低：估算〕。
- **国内安卓商店**（华为、小米、OPPO、vivo、荣耀、腾讯应用宝等）的常见要求 〔待核实·中〕：
  - **企业开发者认证**（营业执照）。
  - **软著证书或电子版权证书**：多数商店要求其中之一，有些类别强制。
  - **APP 备案号**。
  - **隐私合规**：首次启动弹出隐私政策且不得默认勾选；权限按需申请，拒绝后不得频繁再次申请；不得强制捆绑授权；提供第三方 SDK 清单和个人信息收集清单；账户注销通道。依据工信部 2020 年 164 号文、2023 年 26 号文，以及《App 违法违规收集使用个人信息行为认定方法》（2019）。
  - 若面向儿童，需要**儿童隐私政策**。
  - 健康类 App 可能被要求提供资质。我们定位为"练习或放松工具"，不提供医疗服务。
- **等保：** 依据《网络安全法》第21条，网络运营者须履行网络安全等级保护制度。涉及未成年人和健康类数据的系统，建议做**等保二级**备案和测评，费用估计 3–8 万元/年 〔待核实·低：估算〕。部分商店或合作方会要求提供。

### 8.7 若使用 LLM：生成式 AI 规则

- **《生成式人工智能服务管理暂行办法》**（国家网信办等七部门令第15号，2023-07-10 公布，2023-08-15 施行）〔待核实·高〕：
  - 向境内**公众**提供生成文本等服务即在适用范围内。
  - 提供者承担网络信息内容生产者责任和个人信息处理者责任（第9条）。
  - **公开适用人群、场合和用途，采取有效措施防范未成年人过度依赖或沉迷**（第10条）。
  - 不得收集非必要的个人信息，不得非法留存可识别身份的输入信息和使用记录（第11条）。
  - 按规定标识生成内容（第12条）；处置违法内容并报告（第14条）；建立投诉举报机制（第15条）。
  - **具有舆论属性或社会动员能力的**，须做安全评估，并依《互联网信息服务算法推荐管理规定》办理算法备案（第17条）。
- **实务路径** 〔待核实·中〕：
  - 自研或部署模型的提供者走"生成式人工智能服务备案"（俗称"大模型备案"，经省级网信办报国家网信办，含安全评估），周期通常以月计。
  - **通过 API 调用已备案模型**的应用一般走"登记"程序，比备案轻，但仍需提交材料。
  - 不能使用**境外未备案的大模型**面向境内公众提供服务，否则既是出境问题，也是资质问题。
- **《人工智能生成合成内容标识办法》**（2025-09-01 施行）和强制性国标 **GB 45438-2025**：对话或写作等场景的文本需要**显式标识**（如在文本起始、末尾或适当位置提示），文件需要隐式标识（元数据）〔待核实·中〕。
- **《互联网信息服务深度合成管理规定》**（2023-01-10 施行）和**《互联网信息服务算法推荐管理规定》**（2022-03-01 施行，第18条规定了面向未成年人的义务）〔待核实·高〕。
- **Apple 侧** 〔已核实〕：申报 AI 功能；提供大模型或算法备案信息；若使用他人的模型，提供授权或使用协议；必要时提供安全评估截图和报告；**否则不在中国区上架**。
- 2025 年以来，监管对"AI 陪伴"或"拟人化互动"类服务（尤其面向未成年人的）关注上升，是否已出台专门规定需要核实 〔待核实·低〕。
- **建议：** 中国版 v1 **不接 LLM**，用规则题库。这样以上全部可以跳过，Apple 中国区 AI 申报填 No 即可。

### 8.8 NMPA 医疗器械边界、《精神卫生法》与《广告法》

- **《医疗器械监督管理条例》**（国务院令第739号，2021-06-01 施行）〔待核实·高〕：医疗器械包括"所需要的计算机软件"，用途为疾病的诊断、预防、监护、治疗或缓解，以及生理结构或生理过程的检验、替代、调节或支持等。
- 用于**精神或心理疾病**（如抑郁症、焦虑障碍、注意缺陷多动障碍、失眠障碍）**筛查、辅助诊断或治疗**的软件，按医疗器械管理（通常为二类或三类，须注册）。国内已有 ADHD、失眠认知行为疗法等"数字疗法"按器械获批的先例 〔待核实·中〕。分类以《医疗器械分类目录》（子目录 21"医用软件"等）和分类界定结果为准；拿不准时可以向国家药监局医疗器械标准管理中心申请**分类界定** 〔待核实·中〕。
  - 参考：《医疗器械软件注册审查指导原则（2022 年修订版）》《人工智能医疗器械注册审查指导原则》〔待核实·中〕。
- **《精神卫生法》**〔待核实·高〕：
  - 第23条：心理咨询人员不得从事心理治疗或精神障碍的诊断和治疗。
  - 第51条：心理治疗活动应当在医疗机构内开展。
  - 因此，AI 或教练**不得自称"心理治疗"或"心理咨询"**。
- **《广告法》第17条**〔待核实·高〕：除医疗、药品和医疗器械广告外，禁止其他任何广告涉及疾病治疗功能，也不得使用医疗用语或易与药品、医疗器械混淆的用语。
- **中文措辞：**
  - 可用："放松练习""呼吸练习""停一停""日常情绪觉察""日常压力管理""专注练习""练习时长记录""亲子沟通小提示"。
  - 避免："治疗、疗法、数字疗法、诊断、筛查、测评焦虑或抑郁、多动症、心理疾病、改善症状、医用级、临床验证、处方、心理咨询或心理治疗（无资质时）、情绪障碍预警"。

## 9. 研究伦理：家庭试点研究

### 9.1 什么时候需要 IRB 或伦理审查？

| 情形 | 是否需要 | 依据 |
|---|---|---|
| 联邦资助，或所在机构签有 FWA | **需要** IRB，并适用 45 CFR 46 Subpart D（儿童） | Common Rule 〔待核实·高〕 |
| 私营公司自筹资金 | Common Rule 本身不强制；但**马里兰州**要求州内所有人体研究都遵守 Common Rule，纽约等州对联邦法规不覆盖的人体研究也有审查要求 | 〔待核实·中〕 |
| 涉及器械的临床研究（如为申报 FDA 收集安全或有效性数据） | 需要 IRB，并适用 21 CFR 50（含 Subpart D 儿童）和 21 CFR 56 | 〔待核实·高〕 |
| 通过 App 进行**健康相关人体研究** | **Apple 要求独立伦理审查委员会批准**，并要求知情同意（未成年人由家长或监护人同意） | **Apple 5.1.3(iii)(iv)〔已核实〕** |
| 通过 Google Play 进行研究 | 健康声明中有"Human subjects research"类别 | 〔已核实〕 |
| 想发表论文，或与大学合作 | 期刊和高校通常要求 IRB 批准 | 惯例 |
| 纯可用性测试或产品改进（不追求"可推广的知识"） | 按 45 CFR 46.102(l) 一般不算"研究"；**但 COPPA、录音同意、数据保护照样适用** | 〔待核实·高〕 |
| 中国：医疗卫生机构、高校、科研院所开展涉及人的生命科学和医学研究（含心理学方法研究人的心理行为、收集健康和行为数据） | 需要伦理审查 | 《涉及人的生命科学和医学研究伦理审查办法》（2023-02-18）〔待核实·中〕 |
| 中国：企业开展以人为研究参与者的科技活动（含测试、调查、观察） | 涉及敏感领域时应设立科技伦理（审查）委员会，或委托其他单位的委员会 | 《科技伦理审查办法（试行）》（2023-12-01 施行）〔待核实·中〕 |

**建议：** 只要试点收集"压力、情绪、亲子冲突"等结局指标，且受试者是儿童，就**找独立的商业 IRB**（美国常见的如 WCG、Advarra，初审约 $1,500–5,000，属估算 〔待核实·低〕），或与高校伦理委员会合作。在中国，与高校或医院合作，由其伦理委员会审查。

**风险等级：** 预期属于"不超过最小风险"（45 CFR 46.404），只需一位家长许可，加上儿童知情赞同 〔待核实·高〕。

### 9.2 标准文书清单

1. **家长或监护人知情同意书**（Parental Permission Form），内容包括：研究目的、时长和流程；收集的数据，以及**明确列出不收集的内容（不录音、不录朋友）**；风险与收益；保密和数据处理（含第三方共享，如云服务、分析）；留存和销毁时间；自愿参与与随时退出（退出后数据如何处理）；补偿；联系人和 IRB 联系方式；未来使用或二次研究的单独勾选项。内容要覆盖 Apple 5.1.3(iii) 的五项。
2. **儿童知情赞同书**（Child Assent）：按年龄分版本。约 7–11 岁用图文简版；12–17 岁用接近成人版。中国按《民法典》第19–20条：8 周岁以上为限制民事行为能力人，取得监护人书面同意的同时，**也要征得孩子本人同意**；未满 8 周岁由监护人同意，并尽量取得孩子的口头赞同 〔待核实·中〕。
3. **录音、录像、截图的单独授权**（如有访谈）：访谈录音只录参与者本人，并明确不得录到他人。
4. **数据保护附件**：隐私通知、COPPA 的家长直接通知、数据使用协议。
5. **安全与保护流程**（Distress/Safeguarding Protocol）：孩子透露自伤、受虐或被欺凌时怎么处理；研究人员的强制报告义务（美国各州的 mandated reporter 规则；中国《未成年人保护法》第11条的强制报告制度）〔待核实·中〕。
6. **招募材料、补偿说明**（礼品卡金额不得构成不当诱导）、退出表。
7. 可选：美国非 NIH 资助的研究也可以申请 **Certificate of Confidentiality**，由 NIH 酌情签发 〔待核实·中〕。
