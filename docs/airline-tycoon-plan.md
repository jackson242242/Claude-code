## 1. 玩法蓝本：航空霸业2 的核心循环

原作是按**季度回合**推进的航空公司经营模拟，核心循环如下，全部保留：

1. **开局**：选总部城市（停机坪/经济值各异）、选时代起点、设定胜利目标。
2. **每季度回合内的决策**：
   - **谈航权/起降位**：派职员去目标城市谈判，拿到 slot 才能开航线（职员有
     能力值与冷却，谈判可能失败）。
   - **购机/售机**：机型市场随年代演进（螺旋桨 → 喷气 → 宽体 → 超音速），有
     价格、航程、座位数、油耗、维护费差异；制造商不定期打折促销。
   - **开航线**：选两城 + 机型 + 班次，配置头等/商务/经济舱比例、服务等级、
     票价。需求由两城规模、距离、经济、季节、事件共同决定。
   - **营销与周边**：买广告提升份额；投资酒店、旅行社等关联企业赚业外收入。
3. **结算**：点「下一回合」→ 模拟一个季度 → 损益表、客座率、份额、对手动向、
   随机事件播报。
4. **对手**：3 家 AI 航空公司同场竞争同一航线的客源与稀缺 slot。
5. **胜利**：限定年限内达成目标（如称霸 N 个大区 / 利润额 / 乘客数），破产即输。

**为什么回合制适合我们**：没有实时物理/渲染压力，状态就是一棵 JSON 树，Web +
手机浏览器完全扛得住；模拟只在「下一回合」时跑一次，服务端成本极低。

## 2. 差异化卖点：现实新闻驱动的动态事件

原作的随机事件（石油危机、奥运会、战争）是写死的脚本。我们改成**两层事件系统**：

### 2.1 静态事件库（保底，离线可玩）
- 数据驱动：每个事件是一条 JSON（见 §4.3 schema），含触发权重、持续回合数、
  效果修正器。先手写 ~40 条覆盖原作事件类型（油价、灾害、赛事、政策、流行病）。

### 2.2 实时新闻管道（卖点）
```
cron（每 6h，复用本仓库 site-health 同款 GitHub Actions 模式）
  → 拉新闻源（首选 GDELT / RSS 聚合，免费；NewsAPI 备选）
  → Claude API 把航空相关新闻转成结构化 GameEvent JSON
      （强 schema 校验 + 效果数值封顶，防幻觉/防爆表）
  → 入库为「待生效事件池」，新开的回合从池中抽取生效
  → 游戏内以「世界新闻播报」UI 呈现，注明灵感来源的真实新闻标题
```
- 例子：现实油价大涨 → 游戏内未来 4 回合燃油成本 +15%；某地办世界杯（蹭
  Matchday26 热点）→ 相关城市需求 +30%；火山灰/台风 → 区域航线停飞 2 回合。
- **红线**：事件只取「对航空经营的经济影响」，灾难/战争类新闻用中性措辞、不渲染
  细节；LLM 输出必须过 Pydantic 校验，数值越界直接丢弃，管道挂了游戏无感
  （回落到静态库）。

## 3. 产品形态与范围

- **平台**：手机浏览器优先的响应式 Web（PWA 可加桌面图标），桌面浏览器兼容。
- **模式**：MVP 单机（玩家 vs 3 个 AI），存档在服务端（匿名 id + 可选邮箱认领）。
  异步多人（同一世界周榜）列为 V2，不进 MVP。
- **一局时长**：约 40–80 回合（10–20 年游戏时间），手机上每回合 1–3 分钟决策。
- **IP 安全**：不用「航空霸业/Aerobiz」名称与任何原作素材，城市/机型用真实地理
  + 虚构机型名（如 "CJ-900"），玩法机制本身不受版权保护。

## 4. 技术方案（沿用本仓库技术栈与规范）

### 4.1 架构
- **前端**：Next.js (App Router) + TypeScript strict，手机端单页游戏盘面：
  世界地图（SVG/Canvas 自绘，城市为节点、航线为弧线）+ 底部抽屉式操作面板。
  无 Redux：回合内的局部交互用 `useState`，回合结算后整棵游戏状态从 API 重取。
- **后端**：FastAPI。**模拟引擎放服务端**（防作弊 + 方便平衡性热修）：
  `POST /games/{id}/turn` 提交本回合所有指令 → 引擎结算 → 返回新状态 + 事件播报。
- **数据库**：PostgreSQL 存 `games`（状态 JSONB + 版本号）、`events_pool`、
  `news_ingest_log`；开发环境照本仓库惯例可无库回落到内存 + 种子数据。
- **新闻→事件管道**：FastAPI 内的 service + provider 抽象（沿用
  `backend/app/providers/` 的注册表模式：`NewsProvider` 接口 + mock 实现 +
  GDELT 实现），cron 用 GitHub Actions 定时打一个受保护的 ingest 端点。

### 4.2 代码位置
独立新目录 `airline-game/`（前后端自包含），不混入 Matchday26 的 `src/`：
```
airline-game/
  web/        # Next.js 前端（独立 package.json）
  api/        # FastAPI：engine/（纯函数模拟引擎）、providers/news/、routes/
  data/       # 城市表（~60 城）、机型表（~20 型）、静态事件库 JSON
  docs/       # 数值设计表（需求公式、成本模型、平衡参数）
```
模拟引擎写成**纯函数**（state + commands + events → new state），单测可以不碰
HTTP/DB 直接喂 JSON，这是质量门禁的主轴。

### 4.3 GameEvent schema（两层事件共用）
```jsonc
{
  "id": "evt-fuel-spike-2026q3",
  "source": "news | static",
  "headline": "全球油价飙升",            // 播报标题（新闻事件附原文链接）
  "scope": { "kind": "global | region | city | route", "ids": [] },
  "effects": [                            // 全部是有界修正器
    { "target": "fuelCost", "mult": 1.15 },   // mult 限 [0.5, 2.0]
    { "target": "demand",   "mult": 0.9  }
  ],
  "durationTurns": 4,                     // 限 [1, 8]
  "severity": "minor | major"
}
```

## 5. 里程碑（每个都可玩、都过门禁）

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| **M1 核心循环**（先做） | 地图 + 12 城、买机、开航线、定价、回合结算、损益表；纯函数引擎 + 内存存档 | 手机浏览器能完整玩 10 回合不靠脑补；引擎单测覆盖需求/成本公式 |
| **M2 完整经营** | slot 谈判、机型年代演进、舱位/服务、广告、3 家 AI 对手、胜负判定 | 一局 40 回合可分胜负；AI 会抢热门航线 |
| **M3 静态事件** | 事件 schema + 引擎接入 + 播报 UI + 40 条手写事件 | 事件影响在损益表可见、到期自动消退 |
| **M4 新闻管道** | NewsProvider 抽象 + GDELT 实现 + Claude 结构化 + cron + 待生效池 | 真实新闻 6h 内变成游戏事件；管道断了游戏无感 |
| **M5 上线打磨** | PWA、服务端存档、数值平衡、Render 部署、周榜（可选） | lint/typecheck/双测试套件全绿，真机实测一局 |

M1–M3 不依赖任何外部 API，先把「好玩」立住；M4 才引入外部依赖。

## 6. 风险与对策
- **数值平衡难**（经营游戏的命门）→ 数值全部进 `data/` 配置表，引擎纯函数 +
  「快进模拟 N 局」的平衡性脚本，调参不改代码。
- **LLM 生成事件失控** → schema 强校验 + 效果封顶 + 静态库兜底（§2.2 红线）。
- **新闻源配额/失效** → provider 抽象可换源，mock provider 保证开发与演示。
- **范围蔓延**（多人、实时、3D 地图）→ MVP 明确单机回合制 2D，多人进 V2。
