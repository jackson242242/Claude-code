# 实拍工作流 —— 《带老外游上海》(owner footage pipeline, 2026-07-24)

> 老板实拍素材 = 频道最高优先级内容（真人反应是库存素材永远给不了的）。
> 老板在对话框发素材 → Claude 后期 → 预览确认 → 定时发布。

## 系列设定
- 系列名《带老外游上海 | Laowai in Shanghai》EP 编号连载；专属歌单 + 中国美食歌单双归档
- 单集 20-35 秒 Short；老外的脸部反应 = money shot 放第 0 帧
- 语言：现场英语原声保留（这是资产！），中文字幕翻译 + 英文字幕校对双语烧录
- 音乐垫底音量降到 0.4-0.5（原声优先，音乐只补气氛）；调色只用 clean 轻修
- 冲刺期兼容：美食场景集优先排（替换当日 1-2 个库存槽位）；观光场景（外滩 wow
  瞬间）做旅游特别篇不受冲刺限制 —— 实拍永远优先于库存快剪

## 编辑流程（每集）
0. **内容分析先行（owner 2026-08-18）**：任何文案动笔前，先逐条抽帧看清素材里
   真实有什么（地点/人物/动作/可读文字/时段），记录每条的内容清单；
   **文案只许写画面里看得见、或拍摄元数据可证实的东西**（与库存管线
   FOOTAGE-FIRST GATE 同源）。对话框收到的一切照片/视频都进这个素材库，
   照片可作 Ken Burns 段落/封面/社区贴使用。
1. 收到素材 → `node scripts/prep-owner-clip.mjs` 逐条标准化（自动检测 HDR 转 SDR、
   转 1080p30、保留原声）
2. 选片排序（真实反应 > 过程 > 空镜）→ 给老板报剪辑方案一句话
3. bespoke ffmpeg 剪辑（不走库存 assemble 管线）：硬切为主、字幕对齐语音、
   价格/数字弹条照 STYLE.md v2.1
4. 成片 <30MB 压缩版发对话框预览 → 老板一句 OK → 上传（排期或即发）→ 歌单归档
   → published.json/RUNLOG 记录（lane 标 `owner-footage`）
   → **同时写 `state/owner-slots.json`** 认领槽位：
   `{"YYYY-MM-DD": {"a": {"videoId": "...", "title": "..."}}}` —— 例行 run 的
   选题步骤会先读此文件，被认领的槽位当天不再生产库存视频（已写入 playbook）
5. 出镜授权：老外朋友需口头同意出镜发布（拍进素材里最佳）；路人以背景虚化为原
   则。无授权的正脸特写不用。

## 老板 POV 拍摄卡（2026-10-17 起，复制到备忘录；替换旧的"每条 3-10 秒"卡）
> 为什么换：旧卡的 3-5 秒短镜头、烧进画面的字幕、混进原声的音乐，让我们现有母带里
> 只剩约 80 秒能用的 POV。频道观众要的是"真的在那儿"的第一人称感。
- **机位**：胸口或眼睛高度，拿稳，跟着走——镜头就是观众的眼睛（你不用出镜）。
- **声音**：现场声**开着**（脚步、车厢、水声、人声都是资产）；别关麦，别边拍边放歌。
- **长度**：每条**连续 15-60 秒**，拍完整的动作：走过去、坐车/缆车/船、进门、
  付钱、吃第一口。别剪短、别加字幕、别加音乐——后期我来做。
- **名字牌**：每个地点的名字牌或入口，单独拍一条**干净的 5 秒**（这是我们能说出地名的证据）。
- **价格**：门票、价目牌、小票拍照片（价格对比要用）。
- **长走路（只走下面的路径 A）**：每个地点一条 10-30 分钟横屏 4K 连续走路。
- **格式**：Short 素材竖屏 9:16、1080p/30 就够；长走路横屏 4K。
- **别站在放音乐的店铺或街头艺人旁边**（版权音乐会被 Content ID 认领）。
- **人脸**：陌生人和孩子的脸**不拍特写**，除非对方同意（口头同意拍进素材里最好）。
- **规定**：遵守景区禁拍和禁飞（不用无人机）。
- 原文件直传，**别走微信**（会重新压缩、毁画质）。

## 素材怎么传给我（两条路，二选一）
- **路径 A：Google Drive 文件夹 "CHINATRAVEL-raw"**（原始文件、4K 长走路都走这条）。
  计划由 `scripts/fetch-owner-raw.mjs`（**还没写**：切片 3，只在你选 A 后才做；它需要
  你重发 token 时加 `drive.readonly` 权限——这个权限能读你整个 Drive，不想给就走路径 B）
  把新文件拉进临时 /tmp 工作目录，跑 `prep-owner-clip.mjs`。**原文件永远不进 git**；只提交
  处理后的片段（1080x1920、每条 ≤20 MB）和 .meta 到 `runs/owner-footage/<日期>/`；
  长走路在同一个 run 里渲染上传，只提交元数据。
- **路径 B：在 Claude 对话框里直接发**，1080p 导出、每条 ≤60 秒（对话框单个文件约
  ≤30 MB：超了就导出成低一点码率的 1080p，或拆成两条）。处理后像 8 月那样提交。
  这条路没有长走路长视频。
- 之后的剪法见 `automation/youtube/plans/pov-8week.md`（F1 格式）和
  `.claude/commands/youtube-cycle.md` §0c.6。
