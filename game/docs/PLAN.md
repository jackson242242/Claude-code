# 多人对战游戏(UE5 · 动漫剧场版级观感)— 最终规划

> 交付给 **fable** 审核 + 执行。含 (1) 整体规划、(2) MVP 计划、(3) "电影级观感"技术方案、
> (4) AI 美术生成管线、(5) 能力边界与前置条件。
> **已确认参数:** 引擎 UE5 · MVP 1v1/2v2 竞技场 · 第三人称 · 交付=代码优先+资产清单 ·
> 美术=**AI 生成管线 + JJK 邻近原创风(卡通渲染)** · UE 运行机器**暂未定**(做两阶段升级路径)。

---

## 1. Context — 目标、方向、以及不粉饰的边界

老板要做"像 Roblox Rivals 的多人对战,但画面/声效拉到电影特效水准"。经过澄清,方向定为:
**一个第三人称联网竞技场射击原型,画面走"动漫剧场版级"(cel-shading 卡通渲染),风格借鉴
《咒术回战》的气质但用完全原创的角色/名字/设定。**

**"电影级观感"在本项目重新定义为"动漫剧场版级观感"** —— 不是照片写实,而是像高质量 TV 动画/
剧场版那种:强烈的**卡通描边 + 冲击帧 + Niagara 特效爆发 + 速度线 + 戏剧化运镜**。这个方向对本
项目是**利好**:动漫的"电影特效"主要靠**着色器 / 特效 / 运镜编排(偏代码)**,而非昂贵写实资产,
恰好是 fable 能出力的地方。

当前仓库是无关的 Next.js Web App,**无任何 UE 脚手架可复用**(`ZombieSpawner.lua` 是 Roblox 单机
脚本,仅作 PvE 概念参考)。这是 **greenfield UE5 项目**,分支 `claude/multiplayer-battle-cinematic-5fgp9k`
已 checkout。

### 三条诚实边界(诚实第一 · 门禁与可逆)

1. **实时多人有物理上限**,但动漫卡通渲染方向本就不追求写实,这条约束影响很小 —— 反而更好达标。
2. **fable 需要一台能跑 UE5 的机器才能"自己做编辑器的活"。** UE5 要大显卡 + ~100GB,**当前容器
   跑不了**。策略见 §6 两阶段。fable 能写驱动脚本 + 用**渲染截图自检**,但脚本得有机器去跑。
3. **法律红线(IP):** **只做"JJK 邻近的原创风格"** —— 借鉴动漫气质,但角色/名字/设定/招式全原创。
   **绝不复制 JJK 的角色(五条悟/宿傩等)、名称或设定** —— 那是侵权,不做。这条不越线。

## 2. 核心策略(两个复用,最大化 fable 贡献)

- **玩法/联网基座:复用 Epic 官方 Lyra Starter Game。** Lyra 自带**网络复制的 GAS 射击 + 队伍/
  重生/计分 + 武器 + 第三人称相机 + 模块化 GameFeature**。fable 在此之上叠代码/配置,而不是重写。
- **美术:AI 生成管线 + 自写卡通渲染。** fable 编排 **AI 3D 生成(Meshy/Tripo/Rodin)+ 概念图/
  贴图(图像 AI)+ 自动绑定(Mixamo/AccuRIG)**,并**自写 UE 卡通渲染(toon-shading + 描边后
  处理)**。产出**原型级**原创动漫角色。⚠ AI 生成模型的拓扑/绑定通常需真人美术清理才达上线级。

## 4. AI 美术生成管线(fable 编排,原型级品质)

fable 把"造美术"变成"**编排 AI 工具 + 自检**"的流程,尽量不依赖真人:

1. **概念设计:** fable 用图像 AI 生成原创角色概念图(JJK 邻近卡通风,原创造型)。
2. **3D 网格:** 概念图 → **Meshy / Tripo / Rodin** 文本/图生 3D,得到基础角色/武器网格。
3. **绑定动画:** **Mixamo / AccuRIG** 自动绑定 + 套用动作库(移动/瞄准/开火/技能)。
4. **卡通渲染:** fable **自写** UE 的 **toon-shading 材质 + 描边后处理材质 + rim light**(偏代码,
   fable 强项),把写实网格统一成动漫质感 —— **这一步是把 AI 杂牌资产"抹平成一套风格"的关键。**
5. **导入 UE + 自检:** UE Python 脚本批量导入/设材质/生成角色 BP;**渲染截图 → fable 看图评估 →
   迭代**(需 UE 机器,见 §6 阶段二)。

**诚实标注:** 步骤 1、4 的材质/脚本 fable **现在就能写**;步骤 2、3、5 需要**调外部 AI 工具的 API
+ 一台 UE 机器**才能真正跑出资产。品质是**原型级**,商业级仍需美术清理。

## 5. "动漫剧场版级观感"技术方案(实时上限内)

标注 **fable 可代码/配置** vs **需编辑器·资产**。卡通方向让 fable 能做的比例**显著提高**。

- **5.1 卡通渲染(fable 强项):** toon/cel 着色材质、**描边**(后处理或反向壳)、rim light、
  分级阴影、动漫风 bloom。→ *材质/后处理 fable 可写(HLSL 自定义节点 + PP 材质)。*
- **5.2 动漫"电影特效"—— Niagara(fable 写触发/参数):** 招式特效爆发、冲击帧、速度线、粒子、
  能量流。→ *触发/参数 fable 写(GAS Cue);Niagara 系统资产需编辑器搭或用商城件。*
- **5.3 戏剧化运镜 —— Sequencer(fable 写逻辑):** 击杀慢镜、招式入场演出、命中定格。
  (注意 Movie Render Queue 是离线,不用于实时。)→ *触发/相机切换 fable 写;Sequence 资产需编辑器。*
- **5.4 后处理镜头感:** ACES 色调 + 调色 LUT、bloom、色差、胶片颗粒、动态模糊、暗角、TSR 提质。
  → *默认值/CVar fable 可写;关卡 Post Process Volume 摆放需编辑器。*
- **5.5 光照:** 卡通渲染可用较轻的光照(不强依赖 Lumen);仍可选 Lumen 提升环境层次。→ *配置 fable。*
- **5.6 音频 + 众测混音:** MetaSounds 图 + Submix/混响 + 空间化;fable 导出多版本混音 + **设计 A/B
  测听问卷**代替单人耳朵。→ *图/路由/问卷 fable 可写;音源需导入;**问卷分发是对外动作,需老板账号
  授权,且不承诺回收量/流量**(诚实边界)。*

## 6. 两阶段执行路径(因 UE 机器暂未定)

### 阶段一 —— 无 UE 机器(fable 现在就能全量交付的)
- Lyra fork + 裁剪、`.uproject`/`Build.cs`/`Config`(**含卡通渲染 + 动漫后处理配置**)、CI 编译。
- **全部 C++ 游戏框架**:第三人称相机、GAS 属性/开火/伤害、死亡重生、竞技场 GameMode/计分、
  服务器权威联网、Session(NULL/LAN→EOS)、HUD 接口。
- **卡通渲染材质 + 描边后处理**(代码/材质文本)、GAS 特效/音效/运镜的**触发代码**。
- **AI 美术管线脚本**(调 Meshy/SD/Mixamo 的编排代码)+ **UE Python 自动化脚本**(导入/布光/
  生成 BP/渲染截图),写好但需机器运行。
- **概念美术**(图像 AI 出原创角色概念图)、`ASSET_CHECKLIST.md`、各里程碑**人工验收 SOP**。

### 阶段二 —— 一旦提供 UE5 机器 + shell(把天花板顶上去)
- fable 跑上述脚本:**headless 跑 UE、执行 AI 美术管线出资产、导入、布光、渲染截图 → 自己看图
  迭代**,把"编辑器点选 + 视觉判断"自动化掉一大半,人只做最后拍板。

## 7. MVP 里程碑(1v1/2v2 · 第三人称 · 卡通渲染)

**DoD:** 两玩家联网进同一竞技场,第三人称移动+瞄准+射击,血量/命中反馈/死亡+重生,先到 N 杀
结束;画面为卡通渲染 + 描边 + 动漫后处理;开火/命中/击杀有 Niagara 特效 + 空间化音效(占位可)。

- **M0 可编译基座**(fable:fork/裁剪/配置/CI;编辑器:首次生成 BP、进 PIE)
- **M1 单机对枪核心**(fable:相机/GAS/开火/伤害/重生/计分 C++;资产:占位角色+动作)
- **M2 联网化 1v1/2v2**(fable:服务器权威+复制+Session+计分同步;编辑器:双实例手测+HUD)
- **M3 卡通观感层**(fable:卡通材质/描边/后处理/Niagara 触发/MetaSounds 图;编辑器:特效资产/布光/音源)
- **M4 动漫爽点**(击杀慢镜 Sequencer、冲击帧、速度线、击杀反馈)
- **(并行)美术管线**(fable:概念图→AI 3D→绑定→卡通材质统一;阶段二在 UE 机器上跑通)

**演进(非本轮承诺):** 英雄+招式组(GAS 已铺)→ 5v5 + 占点/回合 → 专用服务器 + lag compensation →
匹配/段位 → 美术清理到上线级。
