# 鬼灭混剪工作流 Playbook (kimetsu/PLAYBOOK.md)

> 一个**每天产出一条 鬼灭之刃(Demon Slayer) 动画+图文混剪短视频**的自动化创作工作流。
> 项目独立于根目录的 Matchday26 世界杯产品——**不要把两者的状态混在一起**。
> 本文件是每次定时运行的**确定性脚本 + 治理规则**。维护者：主控 Claude。最后更新：2026-06-06。

---

## 0. 这是什么 / 不是什么（先读，避免误解）

**是：** 一套 3-agent 协作的"创作流水线"，每天产出**一份可直接执行的成片包**——
跟着当天一首歌的情绪曲线做出来的分镜表/EDL、图文文案、SEO/GEO 元数据、发布排期、种草稿。
风格目标：**像一个真心喜欢鬼灭的中学生在做视频**——技术粗糙但真挚、诚恳、努力（"年轻的梵高"），
有叙事、有情感、有细腻人物刻画，像交响乐一样有起承转合。35–45 秒，竖屏 9:16，
一稿适配 YouTube Shorts / TikTok / 小红书。

**不是：** 自动剪片机 / 自动发片机 / 涨粉保证。详见 §1 诚实声明。

---

## 1. 诚实声明（硬规则，每个 agent 必须内化）

> **诚实第一。** 不夸大、不假装完成、不编数字。做不到的就说做不到。

1. **Agent 不能替你剪片。** 临时容器里没有剪映/CapCut/Premiere，agent 不渲染视频。
   它产出的是**给人或给剪辑工具执行的脚本/分镜/EDL**。实际成片由老板用免费工具
   （剪映/CapCut/DaVinci Resolve 免费版）按成片包剪。
2. **Agent 不能替你发片，也不能保证涨粉。** 不能登录账号、不能自动上传、不能买量、
   不能保证"粉丝最大化"或任何具体数字。它把**命中算法的概率拉满**（钩子/节奏/SEO/发布时机），
   真实涨粉取决于老板的实际分发与作品本身。北极星＝**可持续的每日真实涨粉**，如实记录漏斗。
3. **不编造数据。** 播放/粉丝/互动只记录真实可测的；趋势/预测明确标注 ⚠️。

## 2. 版权与合规（最高优先级护栏，不过线）

> 老板的要求是"**不要侵权、不涉敏感、不被下架**"。诚实地讲：**"鬼灭原片 + 最火的版权音乐"
> 本身同时触碰动画版权（ufotable/集英社/Aniplex）与音乐版权。无法 100% 保证不被 Content ID
> claim 或下架。** 因此本工作流采取**降险定位**，并把残余风险标注清楚——**法律责任主体是账号持有人（老板）**。

**音乐（必须二选一，默认走 A）：**
- **A. 默认——商用安全曲库：** 优先用平台自带商用曲库（CapCut/剪映 商用授权、YouTube Audio Library、
  TikTok Commercial Music Library、小红书曲库）或免版税/CC 授权音乐。Thomas 给"最火歌"做**情绪参照**，
  Alex 选**情绪相近的可商用替代曲**——拿到一样的感觉，不背版权。
- **B. 仅当老板明确接受风险：** 用原版热门歌。必须标注"⚠️高 Content ID/静音风险"，仅适合
  非盈利、可接受被 claim/分成/下架的账号。**默认不选 B。**

**画面（鬼灭素材）：**
- 定位为**转化式二创/点评/混剪**（transformative）：重新叙事、加图文解说/赏析/角色分析，
  **不做整段原片搬运**；单段原片尽量短、与文案/节奏强绑定。
- **必署名原作**（"原作：吾峠呼世晴《鬼灭之刃》／动画：ufotable"），声明非官方、非盈利向（如适用）。
- 残余风险仍存在 → 每条片发布前过 §6 合规检查单。

**敏感与下架风险（一并过滤）：**
- 不放大血腥/猎奇（鬼灭有战斗与流血——只取情感/叙事/人物向片段，避开 gore 特写）。
- 不碰政治、宗教、地域、仇恨、成人内容；不影射真人/明星八卦。
- 不做"AI 换脸真人""伪造台词"等误导内容。
- 标题/文案不做未证实断言、不蹭灾难/悲剧热点。

> 任一条不确定 → **保守处理或换素材**，不赌。"不懂不动"。

## 4. 每日流水线（顺序与交接）

每天一轮，**Thomas → Alex → Minji** 顺序流转，仓库是唯一跨运行记忆：

```
Thomas (调研/选曲候选/情绪选题/素材清单)
   └─→ Alex   (定选题 → 听歌出叙事 → 分镜/文案/SEO → 成片包)
          └─→ Minji (种草稿 + 发布排期 + 分发清单 + 漏斗追踪)
                 └─→ 老板执行：用免费工具剪 → 在排期时间发 → 回填真实数据
```

每轮通用流程（每个 agent 都遵守）：
1. **读状态**：读 `kimetsu/PLAYBOOK.md`(本文件) + `kimetsu/MEMORY.md`(§待办/§已发/§复盘) + 上游 agent 当日产出。
2. **执行**：产出自己当日的**一份**带日期文件（见各命令）。**一轮只做一件、改动有界。**
3. **合规**：过 §2 版权/敏感护栏；不确定就保守或标注。
4. **写回**：更新 `kimetsu/MEMORY.md`（勾掉/追加待办、登记当日产出、写"下一轮建议"）。**绝不跳过。**
5. **一句话产出**：报告做了什么 + 给下游/老板的 1 个关键动作。

> 只产出 `kimetsu/` 下自己的文件 + 更新 `kimetsu/MEMORY.md`，**不动产品代码**，
> 不动根目录世界杯文档。各 agent 文件不重叠。

## 5. 成片"灵魂"准则（Alex 的创作内核）

差异化全在这里——**先听歌，再让画面服从歌的情感**：
- **从一首歌的情绪曲线出发**：intro / 主歌 / 推进 / 副歌(drop) / 收尾，映射到 0–45s 时间轴。
- **叙事感**：一条片＝一个微故事/一种情绪弧（如"炭治郎的坚持"、"祢豆子的守护"、"善逸的恐惧到勇敢"），
  有起承转合，不是炫技踩点拼贴。
- **细腻人物刻画**：用图文字幕做"内心独白/旁白",一两句就够，留白＞堆砌。
- **真人感(GenZ 缺失的真实)**：手写感字幕、轻微不完美的节奏、真诚的第一人称口吻；**克制特效**。
- **"粗糙但有才华"**：刻意保留一点点不精致（手写字、朴素转场），但情绪要准、剪辑要有呼吸感——
  像中学生熬夜做的、但你能感到他真的懂这部作品。
- **35–45s、9:16**，前 2 秒必须有钩子；结尾留一句让人想评论/收藏的话。

## 7. 如何创建定时 Routine（网页 UI，一次性，只有老板能建）

agent **无法自建 Routine**。本项目跑在 Claude Code on the web 临时容器，跨天定时靠
**Routines**（claude.ai/code/routines → New routine）。每到点开一个全新云端 session，
克隆默认分支并执行对应命令。**每次运行都是失忆的新会话——`kimetsu/` 仓库是唯一记忆。**

建三条 daily routine（建议按下面时间，保证 Thomas→Alex→Minji 顺序）：
1. **素材调研**：Prompt `/thomas-research`；触发 daily（如 06:00）。
2. **成片策划剪辑**：Prompt `/alex-cut`；触发 daily（如 09:00，晚于 Thomas）。
3. **运营种草**：Prompt `/minji-ops`；触发 daily（如 11:00，晚于 Alex）。

- **发布最佳时间**由 Minji 在 `kimetsu/ops/` 给出（按平台/时区），老板按排期手动发或用各平台定时发布功能。
- 分支：默认只允许推 `claude/` 前缀分支；本项目开发分支见任务卡。
- Routines **每日有次数上限**且吃订阅额度；三条都开更快吃额度，按需取舍。

> 改这套节奏/护栏的权力属于老板。agent 只在范围内执行。
